 For the user reference -- every option with its default and constraints --
 see software-components.md, section "ppgen.sh"; for the explanation, see
 SatPlan/satplan.md, "Generating problems with ppgen".]

arguments to ppgen.sh:
--style <grid | clique>
for clique style:
--clique-size <N>   number places in each clique of roads
--number-cliques <N>   number of cliques
--trucks <N> default is same as number of cliques
--packages <N> default is same as number of cliques
--airplanes <N> default is same as number of cliques
--drive-cost <R> default 1
--fly-cost <R> default 3
In the generated problems, each clique is a set of places with roads each pair in both directions.
There is one airport place in each clique.
In the initial state, packages are initially distributed randomly and evenly between cliques - the number of packages in a clique
differs by at most 1.
Airplanes are similarly distributed among the the airports.
The goal state randomly distributes the packages to locations.

for grid style:
--dimensions <M> <N>  dimensions of the grid. There is a bidirectional road between adjacent places in the grid.
--airports <N> Number of airports, default 2.
--airplanes <N> Number of airplanes, default is number of airports.
--trucks <N> Number of trucks, default is number of airports.
--packages <N> Number of packages, default is same as number of airports.
--drive-cost <R> default 1
--fly-cost <R> default 3
Airports are randomly placed on the grid so as to maximize the minimum pairwise distance between them.
In the initial state, trucks are randomly placed on the grid as are packages.
In the goal state, packages are randomly placed on the grid.

For either styke
The goal is shaped by three independent options.  A goal "object" is a
package, or a truck when --packages is 0 (below).

--destinations N   default 1
Each object gets N distinct destinations, none its own starting place;
reaching any one of them counts as reaching the object's goal.

--require <all | some>   default all
all: every object must reach one of its destinations.  some: at least
one object must reach one of its destinations.

--preferences <none | L H> default none
If preferences is not set to none, every goal is also a preference.  The goals are assigned preference values in the range L to H.  The chosen values
are equally spaced from L to H.  For example, if there are two goals, one is assign L and the other H.
If there are three, then one is assigned L, one (L+H)/2, and the third H.  The order in which preferences
are assigned to goals is random.  Preferences do not change what is
required.  With --require all and one destination every goal is forced,
so preferences are refused there (likewise --require some with a single
object).

--seed N
Seed the random number generator with the integer N.  If not given, the clock is used to create the seed, and the value used is
remembered to be included in the pddl file.

The generated pddl file includes comment lines with the seed (specified or default) and the values of the all of the parameters
that apply to the specified style (including the style itself), including any default values.

--packages 0
Generate a simpler problem with no packages, where the goals are to get
the trucks to their destinations.  Each truck gets a destination other
than its starting place; in clique style the destination is in the
truck's own clique, since roads do not connect cliques.  The number
of airplanes defaults to 0 but may be set with --airplanes.  The goal
options --destinations, --require and --preferences apply per truck.

--knockout N   N an integer 0 to 100, default 0
If set, N percent of the roads are deleted from the problem instance in a
way that preserves connectivity.  For clique style, each clique loses N
percent of its roads.  To preserve connectivity, the generator first
creates a spanning tree for the grid or each clique, and then adds roads
back in until N percent of the roads that would normally be there are
missing.  If the spanning tree already has more than (100 - N) percent of
the roads, it prints the error "Knockout value set too high, <M>% required
to maintain connectivity", where M is the size of the spanning tree(s)
divided by the total number of possible roads, as a percentage.

--mindist N   N an integer, at least 1; grid style only
--maxdist M   M an integer, at least 1 and at least N; grid style only
With either or both, every object that gets goals (the packages, or the
trucks with --packages 0) starts at the origin p1-1, and every
destination is at least N and at most M steps from the origin, counting
the shortest path over roads and airport routes (a flight is one step),
found by breadth-first search from the origin over the roads left after
--knockout.  A truck cannot fly, so with --packages 0 the distance is
over roads alone, as it is for a package when there are no airplanes.
--mindist N --maxdist N puts every destination at exactly N steps.  If
fewer places qualify than the distinct destinations
each object needs (--destinations N), it is an error.
