# FiFO

FiFO is a finite-domain first-order logic language that compiles to propositional CNF for SAT solving. The interpreter is written in Common Lisp (SBCL).

## Project Structure

- `lisp/` — All Lisp sources and the SatPlan axioms (the installable library):
  - `lisp/FiFO.lisp` — Main interpreter: parser, CNF generation, SAT integration, answer extraction. `solve` takes solver keywords (`:solver :cnf-format :preprocessor :preprocessor-techniques :timeout`) that bind the matching globals for the call. A `.wff` CANNOT set any of these: solving policy is the caller's, and `parse-option` rejects the five (plus `*solver-abbreviations*`, listed in `*solve-policy-options*`) with an error naming the replacement. It used to allow them, and because options run during parsing they beat everything — defeating `solve.sh`/`map.sh`'s solver-kind check (which sees only argv) and overriding `planner.lisp`, which `setq`s `*solver*`/`*cnf-format*` and THEN parses the wff, so a file won at every horizon. `.wff`-settable options are now only the generation ones: `*compact-encoding*`, `*mutex-pairwise*`, `*tracing*`, `*satplan-numslices*` (`*wff-settable-options*`), and an `(option ...)` form is SCOPED to the call that read the file. It used to SETQ the global, so it outlived the file: after a wff with `(option *compact-encoding* 0)` every later instantiation in that Lisp ran with compact off, and a wff's numslices overrode the planner's next setq. Now every option lives in a scope that BINDS those variables (`with-wff-option-scope`, via PROGV; an unbound `*satplan-numslices*` stays unbound inside and after), so `parse-option`'s SET reaches only a binding. Two kinds: `:outer` (`instantiate`, `solve-schemas`, `parse`, and `parse-schema-list` itself, so a DIRECT call works without leaking) opens a scope from the caller's values (`*wff-option-base*`) or joins the open one; `:continue` (`parse-same-env`, which every parse goes through, and the prove QUERY that `solve-schemas` parses after the theory) ALWAYS rebinds — from the values the current theory was BUILT under (`*wff-option-snapshot*`: EVERY option, recorded when a :continue scope ends, cleared by setup-global-env), else the caller's — so a caller's LET around the original parse carries into a later `parse-same-env` (planner evidence runs after instantiate returns), and a theory's options, being set inside that binding, never reach an enclosing scope: a second theory in the same call starts from the caller's values. A `/code-review high` of the first version (which joined the outer scope everywhere and recorded only the options the FILE set) found exactly those two holes plus a prove test that could not fail; the design above closes them. `parse-option` outside any scope (only `parse-schema` on a single form) errors, saying what to call. `run-test-options.sh` covers all three options, a caller's LET, parse-same-env continuing its theory (and a caller's LET around it) and not another's, the prove query (its query must be one the compact encoding SPLITS, read off `*tseitin-counter*`), a fresh parse in an open scope, and a direct parse-schema-list. Mutation-checked: no binding fails 5; a continuation joining the open scope fails 3; no snapshot fails 3; the query not continuing fails the prove case; no scope in parse-schema-list fails its case. `propositionalize` takes `:cnf-format` to override the `(OPTION WEIGHTS ...)` line `instantiate` stamps into the `.scnf`; without it the file's recorded format wins (the global `*cnf-format*` is NOT consulted there), so one `.scnf` can be emitted as CNF, WCNF and WCNF-OLD without regenerating. `*solver-timeout*` (default 600 s; 0/-1/nil = unlimited, normalized by `solver-time-limit`) bounds EVERY solver run and is enforced in-process via `sb-ext:run-program :wait nil` + SIGTERM then SIGKILL after `*solver-kill-grace*` — not by shelling out to `timeout`, which is absent on macOS. SIGTERM is the right signal because anytime MaxSAT solvers print their best-so-far model on it. `*preprocessor*` runs MaxPre 2 (preprocess → solve → **reconstruct**); reconstruction is mandatory since MaxPre renumbers variables, and skipping it yields a plausible WRONG answer rather than an error. MaxPre's `reconstruct` parses only `s OPTIMUM FOUND` and needs an `o` line, so `maxpre--reconstruct` normalizes o/s/v before the call and restores the solver's real status after. Preprocessing is barred from the WMC path — MaxPre preserves optimum cost, NOT model count, so it would silently corrupt Z and all marginals; it also errors if `*cnf-format*` is CNF. `weight`/`probability` accept an arbitrary **formula** (not only a literal): a compound argument is reified by `reify-formula` into a fresh interned atom `(WEIGHTED-FORMULA n)` with the count-neutral biconditional `A ⇔ φ` (expanded with the current `*compact-encoding*`, whose `(TSEITIN n)` selectors are defined and count-neutral too — see `lisp/auxatoms.lisp`), and the weight/target rides on `A` (so `P(A)=P(φ)`); literals are unchanged. Still barred from `or`/`not`/`implies`/`equiv` (now an explicit error). These aux atoms are hidden from the default `marginals` listing, shown under `--weighted-only`. `weight` also takes `:odds r` sugar (`odds-to-cost`) for the cost `-ln r`, resolved at parse time: FiFO reads a cost as a likelihood (`P(x) ~ exp(-cost)`), so a cost multiplies the odds in the weighted thing's favour by `exp(-theta)` and asking for a factor r means theta = -ln r. Two things the docstring is careful about because both are easy to get wrong: r is ODDS not a probability (`P = r/(1+r)` — and only for an otherwise FREE literal), and it is a FACTOR on whatever odds the theory already gives the formula, since a weight is a local term — `(weight (and c d) :odds 0.5)` over free c,d starts from a baseline 1:3 and lands at P=1/7, NOT 1/3. pddl2fifo accepts the same spelling at its three cost sites with the SIGN SUPPLIED PER SITE (`pddl-odds-to-cost` = -ln r for an action's `:odds` and a `:fluent-cost`, both of which become FiFO weights; `odds-to-penalty` = +ln r for a `(preference ... :odds r)`, whose weight is a penalty for VIOLATING it, so escaping w is worth odds exp(w)). Hiding that inversion is the entire point — the modeller writes `:odds 2` at either site and means 'twice as likely'. It composes exactly with `recognize.sh --priors-from-preferences`, whose prior is pi ∝ exp(w), so `:odds r` IS prior weight r; recognize.sh's own preference reader resolves `:odds` too, since it parses preferences independently of pddl2fifo and would otherwise reject the sugar the translator accepts. Distinct from `:probability`, which is a LEARNING TARGET the pipeline solves for; `:odds` is a number the modeller could have written out, so the two are alternatives on one spec, not both. On an ACTION, r>1 gives a NEGATIVE cost that rewards including the action — the correct probabilistic reading, but not what is wanted when the number means fuel or time; `:cost` is for those.
  - `lisp/pddl2fifo.lisp` — PDDL → FiFO wff translator (SatPlan); supports the standard `:action-costs` idiom of a cost **function** declared in the domain's `(:functions ...)` and valued in the problem's `:init` (`(= (drive-cost a b) 3)`), so one domain serves problems that price actions differently — a 0-ary function (or one over constants) folds into the action schema, while a function of the action's parameters is emitted as one ground `(cost <act> n)` fact per grounding, since the schema can hold only a single number; every function except `total-cost` must be **static** (an action that writes one is an error — FiFO has no numeric state), a grounding with no `:init` value is an error rather than a silent 0, and `(= (total-cost) n)` must be 0; supports non-recursive `:derived-predicates` (axioms) — `(:derived (P ?args) <GD>)` reified per-slice as `(equiv (holds (P args) s) <body>)`, a third predicate class kept OUT of the `fluents` domain (no frame axioms), usable in goals/constraints/preferences/evidence/derived bodies but not action preconditions/effects/`:init`; recursion, effect/precondition/init uses rejected; supports the PDDL 3.0 con-GD grammar in `:constraints` (`and`/`forall` over the modals; plus `(occur-in-order [M [N]] a1 ... ak)`, ordered GROUND actions at strictly increasing slices within an optional window — leading INTEGERS are the bounds and the rest are actions, which never collide since an action is a list, `N`=-1 means unbounded, and the bare form is exactly the `1 -1` case. The window is a quantifier GUARD on the ObsDone progression with a complementary quantifier FREEZING the chain outside it, deliberately: naming slices M and N+1 would emit a slice constant that may not exist at the horizon, and an ObsDone atom no other clause mentions makes the constraint silently VACUOUS — guarding instead leaves ObsDone(k,numslices) unreachable, so a too-short or past-the-horizon window is UNSAT, like occur-sometime's empty exists. `occur-in-nonstrict-order` is the same operator family with NON-DECREASING slices, so consecutive observations may SHARE one — which FiFO's parallel slices make necessary: strict ordering serializes simultaneous observations, asserting an order the plan never made and charging for it (measured 17 vs the unconstrained 16 on a logistics plan whose two loads are parallel; six IntrusionDetection observations are outright UNSAT strict and reproduce the plan non-strict). It adds a second family `(ObsAt c i s)` — explained by actions up to AND INCLUDING s — recursing on i WITHIN a slice (unrolled to literal integers, so the clauses stay acyclic), with `ObsDone(i,s+1) ⇔ ObsAt(i,s)` carrying it forward; same O(k·numslices), still determined, still count-neutral. ObsAt is both defined and used only under the in-window guard, so no orphan atom is created outside it — a free atom would double the model count. ONE asymmetry is deliberate: two ADJACENT IDENTICAL observations still may not share a slice, since Occurs is boolean per (action, slice) — there is no 'twice at s' — so allowing it would let one occurrence satisfy both and break the guarantee that each observation binds a distinct occurrence; that pair alone falls back to strict. Both reachable from `:constraints` and `--pddl-evidence`, negation included; `*constraint-env*` carries the problem context into `translate-constraint` for the ground-action validation, since the other modals need none. A `declaim ftype` before `translate-constraint` keeps the forward reference from adding to pddl2fifo's two pre-existing undefined-function style warnings; full goal descriptions incl. `forall`/`exists` inside modals, the problem `:goal`, and preference bodies — static-predicate atoms in formulas stay bare literals resolved at instantiation); `:pddl-evidence` translates PDDL modal evidence forms (`translate-evidence-form`: always/at-end/hold-during/occur-sometime/never/at, combined with and/forall, plus the ground-only `occur-in-order` — ordered action observations compiled to determined ObsDone monitor atoms via biconditional progression axioms, count-neutral under WMC — and its negation `(not (occur-in-order …))`, which flips the final assertion to `¬ObsDone(k,numslices)` for R&G's does-not-comply case used by `recognize.sh`) to FiFO and returns them (3rd value) for the planner's separate evidence scnf
  - `lisp/planner.lisp` — smallest-horizon planning driver; `plan--resolve-evidence` checks every evidence literal against the problem's INSTANTIATED clauses before writing the evidence scnf, because FiFO's `parse` mints a fresh proposition for any literal and one the problem lacks appears in no other clause — so the evidence constrained NOTHING and the planner returned its unconditioned answer silently (measured on a 6-slice plan costing 16: `(occurs (fly …) 20)` gave 16, `(occurs (flyy …) 4)` gave 16, only the real constraint gave 20). The two causes get OPPOSITE treatment: a term the problem has at no slice is a typo, wrong at every horizon, so it ERRORS; a real term at an out-of-range slice just means this horizon is too short, so the literal resolves to false (positive literals drop out, leaving `(OR)` — the empty clause, i.e. UNSAT here — and negated ones satisfy and drop the clause), letting the horizon search EXTEND rather than abort. The comparison is against the theory's atoms, NOT the `fluents`/`actions` domains: derived predicates are kept out of `fluents` but are legal in evidence and do appear in the clauses. Also tier-3 conditioning (`--evidence`/`--evidence-file` FiFO forms, or `--pddl-evidence`/`--pddl-evidence-file` PDDL modal forms translated via pddl2fifo, instantiated via `parse-same-env` into a separate `<root>-evidence.scnf`) and `--marginals` (weighted model counting via `--counter maxent|addmc|ddnnf|d4|mc-sat` — the same back ends `marginals.sh --solver` offers; a counter is NAMED, never a path — each external one resolves on PATH through `*addmc*`/`*d4*`/`*walksat*` so it matches every other entry point, and an unknown name is an error. (The old catch-all treated any unrecognised name as an ADDMC path, so `--counter d4` tried to run d4 AS an ADDMC.) `--marginals` loads ddnnf.lisp too). `:restrict :steps|:actions` (`planner.sh --restrict`, 2026-10-29, the user's proposal) makes the cost step a RESTRICTED minimization: the phase-1 SAT plan is interpreted to `<root>-restrict-sat.answer` BEFORE phase 2 overwrites satout and map, then every `(OCCURS a t)` it does not license gets a hard unit clause appended to the phase-2 WCNF (`plan--restrict-wcnf`; the 2022 `h` format, so appending is all it takes) — `:steps` keeps only its (action, slice) pairs, `:actions` its ground actions at any slice. The SAT plan satisfies both, so the restricted problem is never unsatisfiable and optimum ≤ restricted ≤ SAT-plan cost; the SAT plan's own cost comes from one more solve with every action atom pinned (`:pin`), which also checks that the SAT plan is a model of the weighted theory. Refused with `:longer`, since the SAT plan belongs to one horizon. First measurement (the suite's 4×4 at 6 slices of slack: SAT plan 22, optimum 14, both restrictions 22): a single truck's route cannot be shortened by DROPPING drives (each one is needed for location continuity) or by re-timing the SAT plan's own drives — only a route through roads the SAT plan never drove can, and those are forbidden. Tests: `tests/run-test-restrict.sh`.
  - `lisp/auxatoms.lisp` — the clausifier's own atoms and the round-trip guard, loaded by BOTH `FiFO.lisp` and `reweight.lisp` (the counting chain reweight → maxent → wmc → … is also loaded WITHOUT FiFO.lisp, e.g. by learn.sh, so anything those readers call must live here — putting the guard in FiFO.lisp first broke learn.sh with an undefined function). The compact encoding (`*compact-encoding*`, on by default) splits an OR of two multi-clause sub-formulas with a selector; that selector USED TO BE `(gensym "XX")`, and it had two faults. (1) It did not survive the scnf round trip: `instantiate` prints `#:XX711` and every reader's plain `READ` makes a NEW symbol per occurrence, so each clause got its own unconstrained selector and the disjunction constrained NOTHING — measured: `(or (and a b c) (and d e)) (not a) (not d)` reported SAT, a valid `prove` came back COUNTEREXAMPLE, and the two gold files enshrined it. (2) Even with a stable name it was one-way (S→L, ¬S→R), free whenever both sides held, so counts were inflated. Now `tseitin-or` (FiFO.lisp) mints `(TSEITIN n)` DEFINED as the cheaper side D (S⇔D; a multi-literal clause d of D gets H⇔d), so every aux atom is a function of the theory's atoms and SAT/MaxSAT/counts/marginals are all exact. The DEFINITIONS go to `*tseitin-definitions*` and are appended at top level, NOT returned with the formula's clauses — an enclosing OR distributes over those and switches a definition off (that was the first attempt; the property test caught it, 34/300 mismatches). That variable exists only inside `clauses-with-definitions` (the ONLY way a parse becomes a theory: parse-same-env and both prove sites); its global value is `:none`, and minting a selector outside a scope is an ERROR, so no caller can forget the definitions and none can leak from one parse into the next. The cutoff in `multiply-clauses` multiplies out when |L|·|R| ≤ |L|+|R|+1 — NOT when the product is below the selector's full local cost, which a review proposed: that multiplies out more small ORs whose longer clauses make every selector above them dearer (measured: test_alldiff 6824 → 19143 clauses). `reify-formula` now uses the compact encoding too (it forced it off only because of the gensyms; a weight on an exists over 4 values: 19 clauses vs 85, same marginal). The names TSEITIN and WEIGHTED-FORMULA are RESERVED in `parse-proposition` (a user `(tseitin 1)` would otherwise BE the selector, constrain it, and vanish from answers); `*aux-atom-being-defined*` lets reify-formula through for its own atom. Numbering: reset per `parse`, CONTINUED by `parse-same-env` (planner evidence, prove queries), and namespaced under `*aux-atom-namespace*` in `wmc--evidence-clauses`, whose `(parse ...)` restarts at 1 while being conjoined with a theory read from a file — without the namespace P(a) came out 0 instead of 1/3. The namespace is the first of EVIDENCE, EVIDENCE2, … that the theory does NOT already use (`wmc--evidence-namespace`; callers pass the theory's clauses or atom hash), since hypotheses.lisp writes conditioned theories to disk and re-conditioning one must not reuse its names (measured P(b)=0 for 1/2). That defvar lives in auxatoms.lisp because wmc binds it and may load first (a LET of an undeclared variable is silently lexical). `scnf-check-no-gensyms` runs in `instantiate` (over ALL clauses before writing any, so a failure leaves no truncated file), `propositionalize` and `rw--read-scnf`, so a stale file is refused, not misread. `auxiliary-atom-p` hides both aux kinds from every marginal listing and `interpret` drops TSEITIN atoms from answers. `evidence-aux-atom-p` (namespaced only) is the sole exemption from the stray-evidence checks: ddnnf gives such atoms fresh variables and recompiles (copying its atom map only when one is present), and hp--check-evidence skips them; an un-namespaced aux atom in evidence is a stray
  - `lisp/reweight.lisp`, `lisp/maxent.lisp` — weight-learning pipeline; `maxent.lisp` also has `(marginals ...)` (exact marginal inference by enumeration)
  - `lisp/plearn.lisp` — PDDL weight-learning orchestrator (`learn-pddl`)
  - `lisp/mcsat.lisp` — FiFO→MC-SAT bridge: `(marginals-mcsat ...)`, the one **approximate** marginal back end. Shells out ONCE to WalkSAT v58's `-mcsat` mode (which carries the whole MC-SAT loop — outer slice sampling + inner SampleSAT — in C), so a single run yields every marginal. Encoding: MC-SAT rewards satisfaction with non-negative weights (`P(x) ∝ exp(Σ satisfied soft weights)`), so a FiFO cost θ on literal L becomes the soft UNIT clause `¬L` weight θ when θ>0, or `L` weight −θ when θ<0 — same `exp(−θ):1` odds, never a negative weight (MC-SAT's `1−e^{−w}` slice needs `w ≥ 0`); hard clauses + evidence get the `h` prefix. Supports `evidence`/`evidence-file`, `weighted-only`, `scale`, and pass-through sampler flags (`samples`, `burnin`, `seed`, `unitprop`, `walk-prob`, `temp`, `cutoff`). Prints the sampler's `c` diagnostics as `;` comments and **warns when the ESS efficiency is below `*mcsat-efficiency-warning*` (0.1)** — a frozen chain gives wrong marginals, not just noisy ones. Binary found on PATH as `walksat` (`*walksat*`); v57 and earlier are detected and refused (they print help and ignore `-mcsat`). **CDCL seeding** (`seed-from-sat`, default on; `--no-sat-seed` to disable): the hard clauses are solved once with `*solver*` (kissat) and the model passed via walksat's `-init`, because local search alone cannot reach a model of a SatPlan encoding (pb1 survived 400 M flips); a CDCL UNSAT verdict is then a proof, reported immediately. **Do not trust a FROZEN verdict's marginals:** on large SatPlan encodings the chain starts but never moves, returning the seed plan with every marginal pinned at 0/1 — ESS cannot see this (no non-deterministic vars to estimate from), so v58 reports a separate `c mixing:` Hamming-distance line, and `mcsat--frozen-p` surfaces it as a loud warning and a third return value. `--unitprop` makes the check decisive (its free-variable count separates "determined" from "frozen"), so prefer it on
  - `lisp/maxterm.lisp` — FiFO→max-term bridge: `(marginals-maxterm ...)`, `--solver max-term`. NOT a Gibbs marginal — `logit P(a) = beta*(c_min(¬a) − c_min(a))` from 1+n MaxSAT solves (the unconstrained optimum supplies one polarity per atom), i.e. R&G's recognizer with the hypothesis replaced by an atom. Drops the degeneracy term, so it approximates what the WEIGHTS contribute and discards what the COUNTING contributes — on an unweighted theory it returns 0.5 for everything. Output is `(MAXTERM-MARGINAL ...)` deliberately, so `grep MARGINAL` cannot pick it up. Exact on backbone atoms (flagged `[proved]`). Exclusive groups are DETECTED from the theory (at-least-one clause + pairwise at-most-one), never declared in the query — the exact back ends need no declaration, so the query should not repeat what the theory says; `--verify-groups` proves them by SAT instead. At-most-one-but-not-exhaustive groups get a virtual "none" cell. Priors are post-hoc log-odds shifts needing NO re-solve, because a unit cost factors out of the minimisation — exact for the atom it is on, wrong for every other. Uses FiFO's `shift-and-scale-weights`/wcnf writer: raw real weights make a MaxSAT solver emit no objective at all. **Needs an EXACT MaxSAT solver** — default `bin/rc2-maxsat.py` (PySAT RC2, core-guided, prints `s OPTIMUM FOUND`), found beside the script rather than on PATH since FiFO ships it; `--maxsat-solver` selects another. The anytime solvers (tt-open-wbo-inc, nuwls-c) NEVER prove optimality, and since the estimator is a DIFFERENCE of two minima their upper bounds do not cancel; `mt--solve` returns `:unproved` for those and `marginals-maxterm` counts and warns. (Measured on pb1: 15 of 16 solves unproven with the anytime solver, though the values happened to be identical — and rc2 was 2.7x faster.) EvalMaxSAT works, but on macOS ONLY when built with Homebrew GCC — the Apple-clang build compiles cleanly and segfaults instantly, so install-solvers.sh passes a `g++-N` to its cmake (`/usr/bin/g++` is a clang shim). It exits 30 on success, which is fine since `solver-verdict` reads the `s` line.
  - `lisp/hypotheses.lisp` — posteriors over a set of competing hypothesis atoms: `(hypothesis-posterior scnf &key hypotheses evidence baseline counter priors ...)`, behind `marginals.sh --hypotheses`. Dispatches to all six back ends; see the `marginals.sh` entry above for the identity, the guards and the `Weights` trap.
  - `lisp/wmc.lisp` — FiFO→ADDMC bridge: `(wmc ...)` weighted model count and `(marginals-addmc ...)` marginals via the external ADDMC counter (emits MCC weighted CNF, shells out, parses the count). `(wmc-write-wcnf scnf out &key dialect ...)` exposes the writer alone, in `:mcc-2020` (ADDMC's `--wf 4`, still the DEFAULT so no existing caller changes format) or `:mcc-2024` (the competition format from 2021 on, which SharpSAT-TD reads). The two are NOT textually interconvertible and both failure directions are SILENT. 2024 is `p cnf` not `p wcnf`, its weight lines are COMMENTS (`c p weight <lit> <w> 0`, trailing 0 mandatory — SharpSAT-TD matches on exactly 6 tokens where ADDMC took 3 or 4), and crucially the two parsers disagree on an UNSTATED polarity: ADDMC defaults it to 1.0 (`MCC_DEFAULT_LITERAL_WEIGHT`), while SharpSAT-TD INFERS it as `1-w` when the stated side is in [0,1] and HARD-ERRORS otherwise (`preprocessor/instance.cpp:183-205`). FiFO's model is `W(L true)=exp(-theta)`, `W(L false)=1`, i.e. ADDMC's rule — so translating the 2020 weight lines into 2024 syntax substitutes a PROBABILITY reading of every charged literal (measured: Z=1.367879 where the truth is 1.735759 on `(OR A B)`+`(WEIGHT A 1.0)`) and aborts outright on a negative cost, which a learned weight or `(weight ... :odds r)` with r>1 produces. Worse, a reader that skips comments counts the formula UNWEIGHTED and reports it as a weighted count. So the 2024 writer emits BOTH polarities of EVERY variable, each `exp(-cost/scale)` with an absent cost taken as 0 — 2V lines instead of one per charged literal, but then no inference rule of any reader can fire and the file states FiFO's distribution outright. The 2020 path is byte-identical to before (verified against the pre-change writer, negated weighted literals included). The file's SECOND counter is SharpSAT-TD (`marginals-sharpsat`, `wmc … :counter :sharpsat-td`; the macOS port is github.com/HenryKautz/sharpsat-td), fed `:mcc-2024`: `marginals-addmc` and `marginals-sharpsat` are thin wrappers over ONE clamping body, `wmc--marginals`, with `wmc--counter` returning the runner and the dialect. Its count is parsed from the decimal output as an EXACT rational (`wmc--decimal-to-rational`) — never the Lisp reader, which rounds to a double and silently underflows to 0 below 1e-308 (SBCL does not signal; `(float tiny-rational 1d0)` is just -0.0) — and `Z_a/Z` is taken BEFORE converting, so marginals survive a Z of 1e-348 where ADDMC's Z is 0. The gain is EXPONENT range only: SharpSAT-TD never sets MPFR's precision, so its mantissa is the default 53 bits. `wmc` converts Z through `wmc--count-value`, which ERRORS outside the NORMAL double range (subnormals included — they print 17 digits of which few mean anything) rather than return 0 (which reads as UNSAT). The exact-rational parse fixes underflow of a PRODUCT only: every individual weight is still written as a double (both counters parse weights with `std::stod`), so a single cost beyond about ±708 cannot be written — it used to be emitted as `0.0` (a soft cost silently made hard, Z=0, "unsatisfiable") or as a subnormal that sharpSAT aborted on. Now `wmc--write-mcc :fold t` (FiFO's own counting runs only, NEVER `wmc-write-wcnf`, whose file must denote the theory's own Z) unit-propagates (`wmc--unit-propagate`, queue + occurrence lists, linear — it runs once per clamped count) and moves every FORCED literal's cost into a returned log factor, writing that variable with weight 1; under 2024 it also rescales each free variable so its larger weight is 1. Counts are then `(raw, log-factor)` pairs, and `wmc--ratio` takes `raw_a/raw` exactly and adds only the DIFFERENCE of factors. A clamp refuted by UP is a 0 count with no counter run — so `--hypotheses` on the fixture makes 7 calls, not 8. Whatever still does not fit (a FREE atom at cost 720 or -750) is an error naming the atom (`wmc--checked-weight`), in both modes. `wmc--marginals :atoms` restricts the clamps to a few atoms; `hp--marginals` passes the hypotheses, so `--hypotheses` is 1+k runs per pass, not 1+n. The clamped counts then run `:jobs` at a time (`*wmc-jobs*` 4, `marginals.sh --jobs`; Z first and alone) on SBCL threads via `wmc--parallel-map`, each in its own scratch file — measured 25 s → 9 s at 4 jobs on Switch-4. Two traps it handles, both silent: new SBCL threads see a special's GLOBAL value, so a caller's `(let ((*solver-timeout* 2)) …)` would be lost in the workers — the pool captures and rebinds `*solver-timeout*`/`*solver-kill-grace*`/`*default-pathname-defaults*`; and `make-scratch-file-root` draws from one shared random state, so names are taken under `*wmc-scratch-lock*`. `--cache-mb` is a TOTAL budget split across the jobs (at least 100 each), so jobs never multiply memory. The port (since 4382ba7) also cleans up on signals: a SIGTERM/SIGINT/SIGHUP to sharpSAT during the decomposition kills flowcutter's group and unlinks both temp files, then re-raises; an inherited-IGNORED signal stays ignored (nohup; and a non-interactive shell starts background jobs with SIGINT ignored, which is why its test uses SIGTERM/SIGHUP). BOTH counters run through `wmc--run-counter` → `run-program-to-file`, so `*solver-timeout*` bounds them — ADDMC previously had NO timeout, despite the invariant (that function gained `:error-file`, since sharpSAT reports a missing flowcutter on stderr), and ALWAYS pass `-cs` (`*sharpsat-cache-mb*`): unset, SharpSAT-TD sizes its cache from "free" RAM, which its macOS build reads as TOTAL RAM. `*sharpsat-decot*` (1 s) is flowcutter's budget, an anytime search that always uses all of it, on EVERY one of the 1+n counts. Members whose formula instantiates to false are dropped; a non-literal member gets a `(TSEITIN n)` atom DEFINED as the conjunction of its clauses (`define-conjunction-atom`, factored out of `tseitin-or`), so the encodings work on literals. Encodings: pairwise (one binary clause per unordered excluded pair), or the linear chain — order the first family's members x-only labels first, then labels whose two members DIFFER, then labels whose two members are the SAME literal; prefix ORs Pₖ and suffix ORs Sₖ, each a fresh TSEITIN atom with its 3-clause biconditional; each second-family member y at position i gets ¬y∨¬P(i−1), plus ¬y∨¬S(i+1) only when its label's two members differ (for same-literal labels ordered last, the pair (x_j, y_i), j>i, is y_j's prefix clause), and ¬y∨¬P(m) when its label has no first-family member. At-most-one is therefore one prefix chain: 3(m−1)+m clauses. `parse-mutex` writes the cheaper (estimated before building, `mutex-chain-plan`); `*mutex-pairwise*` (wff-settable, scoped like every option) forces pairs, and compact-encoding OFF writes pairs with NO atom at all (a non-literal pair is the product of the two negations). Definitions go to `*tseitin-definitions*`, so a mutex under an OR is fine; under `not`/`implies`-antecedent/`equiv` it is an error (negating it is an exists over pairs — write that), as is a mutex in a static form or with a variable list. Everything is hash/vector indexed: a list `find` per member brought the |X|·|Y| cost back as time. A member's negation is taken from its CLAUSES, never by parsing `(not φ)`: `parse-not` reads `(not (if <false> ...))` as TRUE (an `if` with a false test is vacuous in both polarities — pre-existing, left as is, but classically wrong), so the first version mis-negated a member containing a vacuous `if`; the property test found it.

Its draws come from a SEPARATE random state (`knockout-random-state`: a vector seed — the seed's low two words, a marker, then any higher words, so all of the seed counts while every seed below 2^64 keeps the state it had), so the same seed with and without it differs ONLY in road lines — the suite checks every other line identical — and kept roads print in the original order. 0 does nothing and is recorded only when above 0, so no-knockout output stays byte-identical to the generator before it (checked against HEAD over 6 configurations). `--mindist N` / `--maxdist M` (grid only, either or both) put every goal object at the origin `p1-1` and replace the per-object places function with the places whose BFS distance (`bfs-distances`) from the origin is in N..M (an absent bound is open; the origin, distance 0, never qualifies); the graph is the roads AFTER knockout plus the airport routes, but roads ALONE for `--packages 0`, since a truck cannot fly (mutation-checked: letting trucks count routes makes the truck case fail), and roads alone for packages with `--airplanes 0`, since nothing can fly them (a review found the routes still counted there). The random starts are still drawn and then overwritten, so every later draw — and so the trucks, airplanes and roads — matches the same seed without it; both options are recorded only when set. "Steps" are moves, a flight counting as one, so an airport at the origin collapses distances — the error names the farthest distance there is. (2026-10-14: the lower bound was first spelled `--maxdist`, which read backwards, with a flag `--eqdist` for "exactly N"; it became `--mindist`, `--maxdist` became the real upper bound, and `--eqdist` went, since `--mindist N --maxdist N` says the same. Neither was ever committed, so no recorded file uses the old meaning.) The goal code is generic over a goal-object list (`goal-places` takes a per-object places function), and package-mode PDDL was byte-identical to the generator before it (checked over 8 configurations). The settings block changed with the goal options on 2026-10-14, so files generated before then no longer replay: deliberately, since it is early and no compatibility was kept. `--seed` fixes the draws; without it the clock seeds and the value is still RECORDED, and every generated file opens with the full settings block (defaults included, style-relevant only) that regenerates it byte for byte. (`--require` is always recorded, its default `all` being a spelling.) In the checkout they live under `SatPlan/` because they are domain-specific; `make install` installs them alongside the rest (see `Makefile` above). `SatPlan/evgen.sh` + `evgen.lisp` are the companion EVIDENCE generator for plan recognition (domain-independent, but shelved beside ppgen): given a problem and the `.answer` planner.sh wrote for it, `--slices "1-3,5"` emits the fluents and actions true at those slices as FiFO forms for `planner.sh --evidence-file`, with `--observe "fly,in"` restricting to named fluents/actions and `--negative-evidence 1` also recording what is FALSE. It emits FiFO forms, not PDDL modal ones, because only these can pin a FLUENT to a slice — the modal `at` takes an ACTION and `hold-during` takes a range. `--recognition 1` makes the file usable by `recognize.sh --evidence-kind fifo`: it writes ONE `(and ...)` form instead of a literal per line, which is the whole requirement, since recognize.sh builds the does-not-comply case by wrapping the file's contents in `(not ...)` and `(not A B)` is not a formula (recognize.sh now REFUSES a multi-form file rather than emit that, and names `--recognition 1` in the message — the guard covers the PDDL path too, where the same shape was a SILENT bug: `(not A B)` is read as `(not A)`, so a second observation vanished from the not-comply case while the comply case still used it, leaving the two costs incomparable; measured, `(not A)` and `(not A B)` are both UNSAT where `(not (A B))` costs 14). It also refuses `--negative-evidence 1`, which would collapse the posterior to 0/1. Prefer `--observe` over ACTION names: an action at slice s means slice s at any horizon, but a fluent at the FINAL slice means "at the end" only at the horizon it came from, and recognize.sh picks one horizon for all hypotheses — which it also raises to the largest slice the evidence names, since slice-pinned evidence is unsatisfiable below that and every posterior would be 0. evgen cannot leak a hypothesis: `hypI` are DERIVED predicates and evgen emits from the `fluents` domain, which derived predicates are kept out of. `--export-dataset <dir>` writes the instance in the RAMIREZ & GEFFNER DATASET FORMAT instead — `domain.pddl` (hypothesis rules stripped), `template.pddl` (goal = the `<HYPOTHESIS>` placeholder), `hyps.dat`, `obs.dat`, `real_hyp.dat`, README — for tool chains that do not read FiFO. It is the exact INVERSE of `SatPlan/Examples/Plan_Recognition/make-recognition-instance.lisp`, so the round trip closes and is tested (export → re-import → solve under the exported obs.dat, observations embedding at increasing slices); the exported `hyps.dat` also reproduces the PUBLISHED `IntrusionDetection/hyps.dat` hypothesis for hypothesis. Needs a recognition instance — a goal that is `(or (hyp0) ... (hypN))` of nullary derived predicates, which supplies hyps.dat's ORDER while the domain's `(:derived (hypI) ...)` rules supply its content; anything else is refused. `real_hyp.dat` is READ from the answer's `(HOLDS (hypI) numslices)`, not guessed. Costs are KEPT (an added cost is indistinguishable from an original one, and `add-cost-to-action` skips an action that already has one, so the round trip does not double them). Two limits, repeated in the exported README: obs.dat holds ACTIONS only (a fluent in `--observe` errors, `--negative-evidence 1` is refused), and it is a linear sequence while FiFO slices are PARALLEL, so same-slice actions come out consecutive in an arbitrary order. `--export-constraints <dir>` is the OTHER export, making the opposite trade: it writes the problem with the observations in a `(:constraints ...)` section at their EXACT slices — `(hold-during t t <fluent>)`, standard PDDL 3.0, and `(occur-sometime t t <action>)`, which is NOT (every standard con-GD operand is a STATE formula, so the standard cannot say an action occurred; occur-sometime is FiFO's own). A file containing action observations therefore OPENS WITH A COMMENT naming that requirement, so a recipient learns it from the file rather than a parse error; a fluents-only export omits the note and is plain PDDL 3.0. It writes domain.pddl (unchanged but for `:constraints` in `:requirements`), problem.pddl and a README; needs NO recognition instance, unlike --export-dataset; and keeps fluent observations, which obs.dat cannot represent. `--negative-evidence 1` refused — `(hold-during t t (not f))` would do a negative fluent but nothing says an action did NOT occur. `--export-ordering-constraints <dir>` is the third: ONE `(occur-in-order M N a1 ... ak)` carrying the observations' order and the span they fell in, without pinning any to a slice. Its caveat comment is UNCONDITIONAL — unlike hold-during there is no standard fallback at all. Two observations in the SAME slice are REFUSED, naming the slice: occur-in-order needs strictly increasing slices while FiFO's are PARALLEL, so writing them as a sequence would claim they happened at different slices and the export could come back UNSAT. `--nonstrict-ordering 1` emits `occur-in-nonstrict-order` instead and ACCEPTS the tie, which is the usual answer on a parallel domain. Note `--observe` filters by predicate NAME, so it cannot separate two groundings of the same action — the message says so, and points at `--slices`, `--export-constraints` and `--nonstrict-ordering 1`. Choose between them by what the recipient runs: --export-dataset is order-only and universally readable, --export-constraints keeps the times but needs a planner extended for occur-sometime. Since FiFO reads this dialect the export is verified by SOLVING it — the exported problem must hit the source plan's cost, and moving one constraint to another slice must break it. Everything emitted is validated against the problem's real ground universe, re-derived by parsing the wff with `*satplan-numslices*` bound to the solution's horizon and reading `FLUENTS`/`ACTIONS` out of FiFO's global `Bind` (NOT from the `.map` beside the solution, which `cleanupfifo.sh` deletes). That validation now doubles up with `plan--resolve-evidence` (see `lisp/planner.lisp` above, which closed the same hole on the planner side); evgen's is the earlier line, failing at generation time against the SOLUTION's horizon rather than the planner's working one. An out-of-range slice, an unmatched `--observe` name, a non-SAT solution file and an empty selection are each an error. Without `--domain`, evgen resolves `(:domain ...)` through `resolve-domain-file` and records the file in its settings block; its lookup used to compare the keyword's symbol-name with `":DOMAIN"` (it is `"DOMAIN"`), never matched, and recorded the PROBLEM file as the domain, so the block could not replay — the evgen suite now checks the recorded line. Note fluents run slices 1..N but actions only 1..N-1, so `--slices N` yields fluents only; and `--observe` restricts NEGATIVES too, which it must — one slice of unrestricted negative evidence on a toy 3-package problem is 341 literals (45 fluents + 296 actions), and negative evidence asserts COMPLETE observability, which collapses a recognition posterior rather than sharpening it

**Locating the lisp:** every script sources `bin/fifo-lisp.sh`, which sets and
EXPORTS `FIFO_LISP` by one rule: the variable if set; else `<script dir>/../lisp`
if it holds `FiFO.lisp` (so a checkout's `bin/planner.sh` uses that checkout's
lisp); else `~/lib/fifo/lisp`. `fifo-solvers.sh` sources it too, so `solvers.dat`
always comes from the same directory. (Each script used to carry its own default:
most hard-coded `~/lib/fifo/lisp`, so a checkout's scripts silently loaded the
INSTALLED lisp, and `recognize.sh` defaulted to `../lisp` — `~/lisp` for an
installed copy, which does not exist, so the installed recognize.sh failed unless
`FIFO_LISP` was set.) `ppgen.sh`/`evgen.sh` live in `SatPlan/` in a checkout, so
they source `../bin/fifo-lisp.sh` there and the copy beside them when installed.
Their own `.lisp` is looked for beside the script, then in `$FIFO_LISP`, then in
`$FIFO_LISP/../SatPlan` — the last for an INSTALLED script pointed at a
checkout's lisp/ (as the docs suggest), where the generator is not in lisp/.
The test scripts default `FIFO_LISP` to the checkout's `lisp/`.

**Locating a PDDL domain:** the DOMAIN LIBRARY is `$FIFO_LISP/../pddl` — `pddl/`
in a checkout (holds `clara-logistics.pddl`), `~/lib/fifo/pddl` installed. The
Lisp finds it from where `pddl2fifo.lisp` was LOADED (`*pddl-library-directory*`),
not from a variable, so it always matches the lisp being run. A problem naming
only `(:domain <name>)` is resolved by `resolve-domain-file` (pddl2fifo.lisp; used
by pddl2fifo, plearn and evgen): `<name>.pddl` BESIDE the problem, then in the
CURRENT directory, then in the library. Beside-the-problem is first deliberately:
when the cwd differs, a same-named file there is more likely an unrelated copy, and
planning against it gives a different answer with no error; for the same reason
the chosen file is printed on stderr as `; domain <name>: <path>`, and a miss
lists all three places. The cwd is `sb-unix:posix-getcwd`, not
`*default-pathname-defaults*`, which callers may rebind, and it is parsed with
`sb-ext:parse-native-namestring`: as a plain namestring a directory called
`[old]` or `exp*2` is a WILD pathname, and `probe-file` on one ERRORS rather than
returning nil, so the lookup died instead of falling through to the library. An explicit `--domain` is
taken as given; a BARE name (no `/`) not in the cwd falls back to the library
(`_fifo_find_domain` in fifo-lisp.sh, used by planner.sh, learn-pddl.sh, evgen.sh,
recognize.sh); a name with `/` is never searched for. `learn-pddl` writes a learned
copy of a LIBRARY domain beside the problem, never into the library.

## Key APIs (in lisp/FiFO.lisp)

- `(parse schemas &key static-list)` — Parse FiFO forms to ground clauses (all post-first args are keyword args; `:observation-list` is a deprecated synonym)
- `(instantiate "file.wff")` — File-based: wff -> scnf
- `(propositionalize "file.scnf")` — File-based: scnf -> DIMACS cnf + map
- `(satisfy "file.cnf")` — Run SAT solver (default: kissat)
- `(interpret "file.satout")` — Map SAT output back to symbolic literals
- `(solve "file.wff")` — End-to-end: wff -> solution

## Running

Requires SBCL with Quicklisp. The SAT solver defaults to `kissat` (configurable via `sat-solver` variable).

The weighted-model-counting bridge (`lisp/wmc.lisp`, `bin/wmc.sh`, `marginals.sh --solver addmc`) shells out to a separate **ADDMC** executable — a macOS fork at `github.com/HenryKautz/ADDMC` (built locally at `../ADDMC/addmc`). It is found on `PATH` as `addmc` (the `*addmc*` lisp variable names it — no env var, no `--*-bin` flag: use a different build by putting it earlier on `PATH`). ADDMC is optional — only the WMC features need it.

`marginals.sh --solver mc-sat` (and `marginals-mcsat` in `lisp/mcsat.lisp`) shells out to **WalkSAT version 58 or later** — `gitlab.com/HenryKautz/Walksat`, the `Walksat_v58_MC-SAT` directory, built locally at `../Walksat/Walksat_v58_MC-SAT/walksat`. Found on `PATH` as `walksat` (the `*walksat*` lisp variable). Optional — only `--solver mc-sat` needs it. A pre-v58 walksat has no `-mcsat`, so both the shell script and the test suite probe `-help` for `-mcsat` and refuse/skip rather than silently running the wrong thing.

`marginals.sh --solver sharpsat-td` (and `marginals-sharpsat` / `wmc :counter :sharpsat-td` in `lisp/wmc.lisp`) shells out to **SharpSAT-TD** — a macOS port at `github.com/HenryKautz/sharpsat-td` (of Laakeri/sharpsat-td; builds on macOS with Homebrew GCC and still on Linux), cloned locally at `../sharpsat-td`. Found on `PATH` as `sharpSAT` (the `*sharpsat*` lisp variable), with `flow_cutter_pace17` in the SAME directory (or named by `$SHARPSAT_FLOWCUTTER`). Optional — only that back end needs it.

FlowCutter and SIGTERM (fork, 2026-10-19). sharpSAT gives flowcutter `-decot` seconds, sends its process group SIGTERM — on which flowcutter prints its best decomposition and exits 0 — and SIGKILLs it after 5 s more; an alarm armed before exec is the backstop. One SimpleGrid run on a loaded Mac failed there: flowcutter was still alive 5 s after the SIGTERM, then died of the alarm (status 14), and sharpSAT treated that as a failed count. It did not reproduce on Linux: 2,000 SIGTERMs at random moments (0–1 s, a quarter in the first 5 ms) under 8-way load all ended within 64 ms. Both ends are now robust to it. flowcutter installs its handlers with `sigaction` and treats SIGALRM (and SIGHUP) like SIGTERM, so the backstop yields a decomposition instead of a kill; and when sharpSAT still has to kill it, `RunFlowCutter` returns false and `Treedecomp` discards the output and uses a single bag — slower, but the count is exact. `run-test-sharpsat.sh` has a stand-in flowcutter that ignores SIGTERM and SIGALRM (Z must match the real run's to 1e-12 relative — a weighted count is carried in 53-bit floats, so another decomposition can round the last digit differently) and the real one sent SIGALRM; both fail against the old binaries. A second fork fix (sharpsat-td 3c027a5, 2026-10-19): flowcutter stopped before its FIRST decomposition writes "aborted before any decomposition was computed" with `sizeof`, so with the string's NUL; sharpSAT read the NUL as a line and passed it to `std::stoi`, which threw, and the count aborted. Every count of CLARA's BlocksWorldCosts recognition instance at 15 slices failed this way (2,520-vertex primal graph, no decomposition within the default `-decot 1`). flowcutter now writes the message without the terminator, and sharpSAT's reader skips NULs and blank lines and falls back to one bag on an edge line it cannot parse. The suite has a stand-in printing the old output (Z exact) and the real flowcutter stopped at 0.2 s on a 3,000-vertex graph (no NUL); both fail against the previous binaries.

MC-SAT and the per-hypothesis baseline (2026-10-19). `hp--exact-rows` divides P(h|T,O) by P(h|T) and maps P(h|T) = 0 to ratio 0 — right for an exact counter, where 0 means impossible, wrong for a sampler, where it means only "never visited". On CLARA's TwoPackage grid5x5-2 every MC-SAT run ended "every posterior is zero": the two chains (with and without the evidence) settled in different modes — one package's goals each — so every hypothesis had one estimate 0. A rerun with its files kept showed the mechanism (efficiency 0.03–0.04, both package-1 goals never sampled, the true goal given 0). Now, under mc-sat, a hypothesis sampled under the evidence but never without it is an ERROR naming the mixing failure, and one never sampled at all gets a WARNING that its 0 is the sampler's. The hypotheses suite tests the rule with `hp--marginals` replaced by canned answers (a real chain cannot be made to miss a mode on demand), including that an exact counter's 0 still means impossible; mutation-checked.

Style warnings (2026-10-19). Every script loads the modules as SOURCE with `load`, and SBCL warns about any function not yet defined when a form is compiled — forward references within a file, and calls into a module loaded later or not at all. `FiFO.lisp`'s `(declaim (sb-ext:muffle-conditions cl:style-warning))` silences only FiFO.lisp itself: `load` binds the compiler policy and handled conditions, so a declaim made in one loaded file ends with that file (SBCL 2.4.0 and 2.6.9 alike). The rest are now fixed at the source: `(declaim (ftype function …))` for the forward and cross-module references in ddnnf, pddl2fifo, planner, plearn and evgen (the form planner.lisp and pddl2fifo.lisp already used), and planner's unused `n` parameter of `plan--resolve-evidence` removed. Checked by loading FiFO.lisp and then each module ALONE — the fewest definitions any load order can give — with no diagnostic left.

Found on `PATH` as `d4` — d4v2 builds it as `demo/compiler/build/compiler` and `install-solvers.sh` installs it under the short name (the `*d4*` lisp variable). Optional — only `--solver d4` needs it. d4 compiles only the Boolean structure; FiFO smooths the dump and applies weights at the leaves, reusing all the ddnnf circuit machinery.

**Important:** SBCL on this system requires `--eval` (long form); `-e` is not recognized and silently drops all eval forms.

## Testing

All test files and scripts live under `tests/`. Two test runners (must be run from inside `tests/`):

```sh
cd tests
bash run-test-instantiate.sh <testname>   # e.g. bash run-test-instantiate.sh test_all_exists
bash run-test-solve.sh <testname>         # e.g. bash run-test-solve.sh test_simple_deduction
```

`run-test-instantiate.sh` runs `instantiate` on `tests_instantiate/<testname>.wff`, writes `tests_instantiate/<testname>.scnf`, and cats the output.

`tests/run-test-ddnnf-eval.sh` (runnable from anywhere) covers the d-DNNF circuit evaluator and the d4 import guards. The evaluator's DOWN pass gives each child of an AND node the product of its siblings' values; the first version recomputed that product for every child, O(k²) per node, and smoothing makes AND nodes wide (up to 1,007 children on a 7×7 SimpleGrid circuit: Σk² ≈ 1.8 billion multiplications against 6 M AND edges), so one query took 25 s and consed 58 GB. It now uses prefix and suffix products — O(k), no division, so a zero-valued sibling (an evidence clamp) stays exact — with leaf weights computed once per query and double-float declarations: 0.03 s, marginals identical to 5.6e-17 over 40 circuit/evidence cases. The load-bearing case is the PROPERTY test, `tests/ddnnf-eval-property.lisp`: random smooth d-DNNFs built directly as structs, random leaf costs and clamps, Z and every marginal against brute-force enumeration of the circuit's Boolean value; some trials force a root AND of 17+ children, past the 16-slot scratch arrays; it refuses to pass with no wide AND, no zeroed leaf, or only 0/1 marginals. Mutation-checked: not copying the prefix products when the scratch arrays grow gives 48 mismatches, dropping the suffix factor 544. The import guards came from a `/code-review high` of the bit-vector importer: root detection took whichever parentless node MAPHASH returned last, so a truncated dump (d4 crashes from SimpleGrid 8×8 on) would build one fragment and root-smooth over the variables the others held — a wrong Z with no error; it now requires exactly one parentless node (mutation: the old rule builds the suite's two-root dump as Z = 4), and `ddnnf--run-d4` refuses ANY nonzero d4 exit, since d4 exits 0 on SAT and UNSAT alike and a crash can leave a partial dump. Out-of-range variables in a dump or a saved circuit get a named error instead of an array-index one. The importer used to keep one nvars-bit scope vector per node for the whole build (≈1.5 GB at 9×9) and walk the circuit twice; it now builds in ONE pass, freeing each node's scope as soon as its last parent has used it, packs arc literals, and skips d4's false arcs.

**Packed circuit and binary files.** The circuit was a vector of `dnode` structs, each with a list of children — a struct header per node and a cons cell per edge — and a text `.dnnf` that took longer to read than to query. It is now the `dnodes` struct of parallel typed arrays — `types` (u8), `lits` (s32), `kstart` (CSR offsets, n+1) and `kids` (u32) — read through `dns-type`/`dns-lit`/`do-dns-kids`; the builder (`bld-add`, `bld-finish`, which trims) and both evaluator passes work on the arrays directly. Persistence keeps text format v1 unchanged — the streaming writer is byte-identical to the old one, and the reader is a streaming scanner (`dscan`) rather than one READ of the whole file as a single form — and adds a binary `.dnnfb`: magic `FIFODNB1`, a byte-order mark and the counts N/K/M as u64, the metadata as a UTF-8 s-expression, then the four arrays as they lie in memory, every section 8-byte aligned, written and read with raw `unix-write`/`unix-read` (the file size is checked against the counts before anything is allocated, so a truncated file is refused rather than read short). `ddnnf-load` dispatches on the magic; `--save-circuit x.dnnf` writes both files. Both readers run the same checks (`ddnnf--check-nodes`: types in range, children strictly earlier, leaves childless, variables in range). The binary file is only 1–16% smaller than the text: the u64 offsets and u32 child ids are about as long as the decimal text they replace. Its point is load time. A fresh projected d4 compile of grid8x8-1 (d4 plus import, with 2-observation evidence) gives Z and marginals identical to the old importer's, at peak RSS 0.98 GB against 1.64 GB; the time, 45–52 s either way, is d4's and varied by more than the difference between the two importers (the order flipped between two runs). On SimpleGrid grid9x9-1 and grid9x9-2 (2.8 M and 3.4 M d4 nodes) the fd0d0b9 importer crashed SBCL's garbage collector ("no size function for object", 12 GB heap) after d4 had finished; the new one imports both, and their model counts equal the independent walk counts (16,913,390 and 17,737,109). `marginals.sh --timeout` / `recognize.sh --timeout` (2026-10-17) set `*solver-timeout*`, whose 600 s default recognize.sh had no way to change: in the SimpleGrid sweep, 36 of 144 7×7 SharpSAT-TD runs failed on one count over 600 s inside a 1200 s run limit. The review found two problems there, both fixed: any negative value was accepted and meant "no limit", so a stray dash (`--timeout -300`) silently removed the cap (only 0, -1 and none are accepted now); and a max-term solve stopped by the limit returns an upper bound (`:best`), which marginals-maxterm's closing WARNING did not count (hypotheses.lisp already did), so a short limit fed two upper bounds into the difference unannounced — the suite now checks it with a stand-in solver that reports a cost and stalls. A `/code-review high` of the circuit change found, and these were fixed: `--save-circuit x.dnnfb` wrote TEXT into x.dnnfb and the binary into x.dnnfb.dnnfb, so every reload took the slow path (a `.dnnfb` name now writes the binary alone, which is also the way to skip the text); a d4 node line with no id was stored under NIL and surfaced as a misleading two-roots error; a saved circuit with no `:NVARS` hit a bare type error before the check that names it; arc literals were allocated twice; and `bld-add`'s node cap, which d4 imports also pass through, said "use --solver addmc" while marginals.sh refused `--node-limit` with d4 — it is now accepted there. d4 at first still ran without `*solver-timeout*`, since the 600 s default would cut 9×9 compiles that succeed (d4 alone takes 490–570 s there); on 2026-10-19 the user chose to bound it like every other solver, so `ddnnf--run-d4` now goes through `run-program-to-file`, and a long compilation needs `--timeout` (CLARA's compile scripts pass their own limit). A stopped compilation is an error — a circuit has no partial answer. At the same time `run-program-to-file` began signalling the solver's whole PROCESS GROUP (SBCL makes each child a group leader): CLARA's d4 shim is a wrapper that does not exec, and SIGTERM/SIGKILL to the wrapper alone left the real d4 running, orphaned. The ddnnf-eval suite checks both with a stalled stand-in d4 that is such a wrapper; mutation-checked (no timeout: 62 s and a different error; killing the leader only: its child survives). The suite's "circuit files" cases: a hand-written text circuit with awkward atom names (a string containing `)`, a `|x y|` symbol) whose Z is checked by hand, a text→binary→text→binary round trip, `--save-circuit` writing both files with `--circuit` on either matching maxent, and a truncated binary and a forward child both refused; mutations of the scanner's string handling, the node checks and the binary writer are each caught.

`tests/run-test-mutex.sh` (runnable from anywhere) covers MUTEX: closed-form counts (at-most-one of 20 = 21 models, two disjoint families of 10 = 2047, equal labels not excluded = 9), counted over every atom so a free aux atom doubles them; the property test `tests/mutex-property.lisp` (random families, guards, overlaps and member formulas, default / pairwise / compact-off, each against the definition written out pair by pair by the test itself and counted by the test's own DPLL counter — 24 atoms, too many for a truth table); the switch and its scope; a SatPlan logistics problem (LogisticsCosts pb3, 10 slices) planned to the same optimum both ways from fewer clauses (needs EvalMaxSAT_bin); and the refused misuses. Its temp dir has no `.` (map.sh). The property test refuses to pass unless the linear encoding fired and some member needed its own atom. Mutation-checked: no suffix clauses 23 mismatches; a prefix atom not forced false 99; a member atom one-way 42; every shared label treated as same-literal 10 — but 0 until the generator learned to MIX same- and different-literal labels in one mutex (an `(and (if (< j k) …) (if (>= j k) …))` member), and 0 with 8 labels, where the different-literal case never made the chain cheaper; the equal-label pair excluded too 136. Its first mutation runs passed vacuously because the mutated FiFO.lisp copy failed to load (no solvers.dat beside it) — check that a mutation run actually ran.

`tests/run-test-tseitin.sh` (runnable from anywhere) is the compact-encoding suite. The load-bearing case is the PROPERTY test, `tests/tseitin-property.lisp`: random formulas instantiated with compact ON and OFF, each through the real scnf file round trip, counted by brute force over EVERY atom against the formula's own truth table — so a free or under-defined aux atom shows as a factor of 2. It REFUSES to pass if no formula produced a TSEITIN atom: its first version passed vacuously because `(option *compact-encoding* 0)` in a wff then SETQ'd the global, which stayed off for every later instantiation in that process (hence its per-call LET, kept though the leak is now fixed — see the option scope under `lisp/FiFO.lisp`). Mutation-checked: dropping the D→S clause gives 61/300 mismatches, dropping the d→H clauses 49, returning the definitions inside the OR 34. Its fixed examples use a 4-OR-3 disjunction, since a smaller OR is multiplied out and would exercise nothing. Also the UNSAT and prove cases, exact marginals with aux hidden, a weighted exists compact vs explicit, re-conditioning an already-conditioned theory (mutation-checked: a fixed EVIDENCE namespace gives P(b)=0 for 1/2 — its first EV2 left a single model, all marginals 0/1, and passed vacuously under the mutation), the reserved names refused in a wff and in evidence, the two gold theories against HAND-COMPUTED counts (2^16−5^4 = 64911 and 2^28−29^4 = 267728175, since compact-off is astronomically large for both; alldiff is counted by SharpSAT-TD, as FiFO's own d-DNNF compiler exhausts the heap on it), compound `--evidence` against the same evidence instantiated in, the namespace, parse-same-env numbering, and both readers refusing a gensym. Against the pre-fix code 13 of 17 fail (the old nested-exists gold counted ~2e165 models, not 64911).

`tests/run-test-docs.sh` (runnable from anywhere) checks that every flag in `ppgen.sh`'s and `evgen.sh`'s ARGUMENT PARSER (the `case` arms, not the --help text, so a flag added only to the parser is caught) appears in that script's option table in `software-components.md`, which is the user REFERENCE for both (every option, default, rule); `satplan.md`'s two sections are the EXPLANATION (topologies, encodings, choosing an output, caveats) and link to it rather than restating defaults. It refuses to pass if a parser yields fewer than 10 flags, so a change in the parser's shape cannot make it vacuous. A flag must appear as a WHOLE token opening a code span (followed by a space, backtick, or the backslash of `\|`) — a substring match let an undocumented `--obs` pass on the strength of `--observe`, and a case pins that. Mutation-checked: removing one row's flag name fails it.

`tests/run-test-paths.sh` (runnable from anywhere) is the lisp-location and domain-lookup suite. Lisp: a checkout script with `FIFO_LISP` unset gets the checkout's lisp, `FIFO_LISP` wins, it is exported to children, an installed copy (a real `make install` into a throwaway HOME) gets `~/lib/fifo/lisp`, a `../lisp` WITHOUT FiFO.lisp is not taken, and the installed `recognize.sh` and `ppgen.sh` run with `FIFO_LISP` unset (recognize.sh used to fail on solvers.dat). Domains: library when nothing is beside or in the cwd, cwd before library, beside before cwd, a miss listing all three places, `--domain` bare-name fallback, a `/` name taken literally, learn-pddl's learned copy of a library domain landing beside the problem, and evgen recording the library file. The ORDER cases are built to FAIL under the wrong order rather than just report another path: the file a correct search must skip is broken PDDL. Also a SYMLINKED lisp directory with a stale `pddl/` beside the link: `_fifo_find_domain` must use `cd -P` (pwd -P alone is not enough), since its `-f` test follows the link physically while a logical `cd` applied `..` to the text and printed the STALE path (mutation-checked: a logical cd reads the broken stale copy). Also a cwd named `[old]` or `exp*2` falling through to the library, and an installed ppgen.sh with `FIFO_LISP` at a checkout's lisp/. Its `make install` passes BINDIR and LISPDIR explicitly, since the Makefile's `?=` would take exported ones and install the working tree over the user's real copy. Mutation-checked: swapping beside/cwd fails the order case (end of file reading the broken copy), dropping the library check makes learn-pddl write into the library, the old namestring parse of the cwd fails the wildcard case, and dropping the `../SatPlan` lookup fails the installed-generator case. The domain cases skip without kissat/tt-open-wbo-inc, which planner.sh validates even for `--stop-after wff`.

The full suite runs from the repo root with `bash bin/run_regression_tests.sh` (it tests `lisp/` by default; set `FIFO_LISP` to test an installed copy).

### Known issues

- Nested `exists` with `(option compact-encoding 0)` causes exponential clause blowup (cross-product expansion). Keep domains small (≤3 values) or omit the option to use Tseitin encoding.
- `test_nested_exists_nocompact.wff` uses 3 boys / 2 girls to stay tractable with compact-encoding disabled.
- `test_nested_exists_compact.wff` uses full 4-boy / 4-girl domains with compact-encoding enabled.
