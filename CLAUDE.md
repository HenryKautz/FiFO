# FiFO

FiFO is a finite-domain first-order logic language that compiles to propositional CNF for SAT solving. The interpreter is written in Common Lisp (SBCL).

## Project Structure

- `lisp/` — All Lisp sources and the SatPlan axioms (the installable library):
  - `lisp/FiFO.lisp` — Main interpreter: parser, CNF generation, SAT integration, answer extraction. `solve` takes solver keywords (`:solver :cnf-format :preprocessor :preprocessor-techniques :timeout`) that bind the matching globals for the call. A `.wff` CANNOT set any of these: solving policy is the caller's, and `parse-option` rejects the five (plus `*solver-abbreviations*`, listed in `*solve-policy-options*`) with an error naming the replacement. It used to allow them, and because options run during parsing they beat everything — defeating `solve.sh`/`map.sh`'s solver-kind check (which sees only argv) and overriding `planner.lisp`, which `setq`s `*solver*`/`*cnf-format*` and THEN parses the wff, so a file won at every horizon. `.wff`-settable options are now only the generation ones: `*compact-encoding*`, `*tracing*`, `*satplan-numslices*`. `propositionalize` takes `:cnf-format` to override the `(OPTION WEIGHTS ...)` line `instantiate` stamps into the `.scnf`; without it the file's recorded format wins (the global `*cnf-format*` is NOT consulted there), so one `.scnf` can be emitted as CNF, WCNF and WCNF-OLD without regenerating. `*solver-timeout*` (default 600 s; 0/-1/nil = unlimited, normalized by `solver-time-limit`) bounds EVERY solver run and is enforced in-process via `sb-ext:run-program :wait nil` + SIGTERM then SIGKILL after `*solver-kill-grace*` — not by shelling out to `timeout`, which is absent on macOS. SIGTERM is the right signal because anytime MaxSAT solvers print their best-so-far model on it. `*preprocessor*` runs MaxPre 2 (preprocess → solve → **reconstruct**); reconstruction is mandatory since MaxPre renumbers variables, and skipping it yields a plausible WRONG answer rather than an error. MaxPre's `reconstruct` parses only `s OPTIMUM FOUND` and needs an `o` line, so `maxpre--reconstruct` normalizes o/s/v before the call and restores the solver's real status after. Preprocessing is barred from the WMC path — MaxPre preserves optimum cost, NOT model count, so it would silently corrupt Z and all marginals; it also errors if `*cnf-format*` is CNF. `weight`/`probability` accept an arbitrary **formula** (not only a literal): a compound argument is reified by `reify-formula` into a fresh interned atom `(WEIGHTED-FORMULA n)` with the count-neutral biconditional `A ⇔ φ` (expanded with `*compact-encoding*` off so no gensyms leak into the `~S` scnf round-trip), and the weight/target rides on `A` (so `P(A)=P(φ)`); literals are unchanged. Still barred from `or`/`not`/`implies`/`equiv` (now an explicit error). These aux atoms are hidden from the default `marginals` listing, shown under `--weighted-only`.
  - `lisp/pddl2fifo.lisp` — PDDL → FiFO wff translator (SatPlan); supports the standard `:action-costs` idiom of a cost **function** declared in the domain's `(:functions ...)` and valued in the problem's `:init` (`(= (drive-cost a b) 3)`), so one domain serves problems that price actions differently — a 0-ary function (or one over constants) folds into the action schema, while a function of the action's parameters is emitted as one ground `(cost <act> n)` fact per grounding, since the schema can hold only a single number; every function except `total-cost` must be **static** (an action that writes one is an error — FiFO has no numeric state), a grounding with no `:init` value is an error rather than a silent 0, and `(= (total-cost) n)` must be 0; supports non-recursive `:derived-predicates` (axioms) — `(:derived (P ?args) <GD>)` reified per-slice as `(equiv (holds (P args) s) <body>)`, a third predicate class kept OUT of the `fluents` domain (no frame axioms), usable in goals/constraints/preferences/evidence/derived bodies but not action preconditions/effects/`:init`; recursion, effect/precondition/init uses rejected; supports the PDDL 3.0 con-GD grammar in `:constraints` (`and`/`forall` over the modals; plus `(occur-in-order [M [N]] a1 ... ak)`, ordered GROUND actions at strictly increasing slices within an optional window — leading INTEGERS are the bounds and the rest are actions, which never collide since an action is a list, `N`=-1 means unbounded, and the bare form is exactly the `1 -1` case. The window is a quantifier GUARD on the ObsDone progression with a complementary quantifier FREEZING the chain outside it, deliberately: naming slices M and N+1 would emit a slice constant that may not exist at the horizon, and an ObsDone atom no other clause mentions makes the constraint silently VACUOUS — guarding instead leaves ObsDone(k,numslices) unreachable, so a too-short or past-the-horizon window is UNSAT, like occur-sometime's empty exists. `occur-in-nonstrict-order` is the same operator family with NON-DECREASING slices, so consecutive observations may SHARE one — which FiFO's parallel slices make necessary: strict ordering serializes simultaneous observations, asserting an order the plan never made and charging for it (measured 17 vs the unconstrained 16 on a logistics plan whose two loads are parallel; six IntrusionDetection observations are outright UNSAT strict and reproduce the plan non-strict). It adds a second family `(ObsAt c i s)` — explained by actions up to AND INCLUDING s — recursing on i WITHIN a slice (unrolled to literal integers, so the clauses stay acyclic), with `ObsDone(i,s+1) ⇔ ObsAt(i,s)` carrying it forward; same O(k·numslices), still determined, still count-neutral. ObsAt is both defined and used only under the in-window guard, so no orphan atom is created outside it — a free atom would double the model count. ONE asymmetry is deliberate: two ADJACENT IDENTICAL observations still may not share a slice, since Occurs is boolean per (action, slice) — there is no 'twice at s' — so allowing it would let one occurrence satisfy both and break the guarantee that each observation binds a distinct occurrence; that pair alone falls back to strict. Both reachable from `:constraints` and `--pddl-evidence`, negation included; `*constraint-env*` carries the problem context into `translate-constraint` for the ground-action validation, since the other modals need none. A `declaim ftype` before `translate-constraint` keeps the forward reference from adding to pddl2fifo's two pre-existing undefined-function style warnings; full goal descriptions incl. `forall`/`exists` inside modals, the problem `:goal`, and preference bodies — static-predicate atoms in formulas stay bare literals resolved at instantiation); `:pddl-evidence` translates PDDL modal evidence forms (`translate-evidence-form`: always/at-end/hold-during/occur-sometime/never/at, combined with and/forall, plus the ground-only `occur-in-order` — ordered action observations compiled to determined ObsDone monitor atoms via biconditional progression axioms, count-neutral under WMC — and its negation `(not (occur-in-order …))`, which flips the final assertion to `¬ObsDone(k,numslices)` for R&G's does-not-comply case used by `recognize.sh`) to FiFO and returns them (3rd value) for the planner's separate evidence scnf
  - `lisp/planner.lisp` — smallest-horizon planning driver; `plan--resolve-evidence` checks every evidence literal against the problem's INSTANTIATED clauses before writing the evidence scnf, because FiFO's `parse` mints a fresh proposition for any literal and one the problem lacks appears in no other clause — so the evidence constrained NOTHING and the planner returned its unconditioned answer silently (measured on a 6-slice plan costing 16: `(occurs (fly …) 20)` gave 16, `(occurs (flyy …) 4)` gave 16, only the real constraint gave 20). The two causes get OPPOSITE treatment: a term the problem has at no slice is a typo, wrong at every horizon, so it ERRORS; a real term at an out-of-range slice just means this horizon is too short, so the literal resolves to false (positive literals drop out, leaving `(OR)` — the empty clause, i.e. UNSAT here — and negated ones satisfy and drop the clause), letting the horizon search EXTEND rather than abort. The comparison is against the theory's atoms, NOT the `fluents`/`actions` domains: derived predicates are kept out of `fluents` but are legal in evidence and do appear in the clauses. Also tier-3 conditioning (`--evidence`/`--evidence-file` FiFO forms, or `--pddl-evidence`/`--pddl-evidence-file` PDDL modal forms translated via pddl2fifo, instantiated via `parse-same-env` into a separate `<root>-evidence.scnf`) and `--marginals` (weighted model counting via `--counter maxent|addmc|ddnnf|d4|mc-sat` — the same back ends `marginals.sh --solver` offers; a counter is NAMED, never a path — each external one resolves on PATH through `*addmc*`/`*d4*`/`*walksat*` so it matches every other entry point, and an unknown name is an error. (The old catch-all treated any unrecognised name as an ADDMC path, so `--counter d4` tried to run d4 AS an ADDMC.) `--marginals` loads ddnnf.lisp too)
  - `lisp/reweight.lisp`, `lisp/maxent.lisp` — weight-learning pipeline; `maxent.lisp` also has `(marginals ...)` (exact marginal inference by enumeration)
  - `lisp/plearn.lisp` — PDDL weight-learning orchestrator (`learn-pddl`)
  - `lisp/mcsat.lisp` — FiFO→MC-SAT bridge: `(marginals-mcsat ...)`, the one **approximate** marginal back end. Shells out ONCE to WalkSAT v58's `-mcsat` mode (which carries the whole MC-SAT loop — outer slice sampling + inner SampleSAT — in C), so a single run yields every marginal. Encoding: MC-SAT rewards satisfaction with non-negative weights (`P(x) ∝ exp(Σ satisfied soft weights)`), so a FiFO cost θ on literal L becomes the soft UNIT clause `¬L` weight θ when θ>0, or `L` weight −θ when θ<0 — same `exp(−θ):1` odds, never a negative weight (MC-SAT's `1−e^{−w}` slice needs `w ≥ 0`); hard clauses + evidence get the `h` prefix. Supports `evidence`/`evidence-file`, `weighted-only`, `scale`, and pass-through sampler flags (`samples`, `burnin`, `seed`, `unitprop`, `walk-prob`, `temp`, `cutoff`). Prints the sampler's `c` diagnostics as `;` comments and **warns when the ESS efficiency is below `*mcsat-efficiency-warning*` (0.1)** — a frozen chain gives wrong marginals, not just noisy ones. Binary found on PATH as `walksat` (`*walksat*`); v57 and earlier are detected and refused (they print help and ignore `-mcsat`). **CDCL seeding** (`seed-from-sat`, default on; `--no-sat-seed` to disable): the hard clauses are solved once with `*solver*` (kissat) and the model passed via walksat's `-init`, because local search alone cannot reach a model of a SatPlan encoding (pb1 survived 400 M flips); a CDCL UNSAT verdict is then a proof, reported immediately. **Do not trust a FROZEN verdict's marginals:** on large SatPlan encodings the chain starts but never moves, returning the seed plan with every marginal pinned at 0/1 — ESS cannot see this (no non-deterministic vars to estimate from), so v58 reports a separate `c mixing:` Hamming-distance line, and `mcsat--frozen-p` surfaces it as a loud warning and a third return value. `--unitprop` makes the check decisive (its free-variable count separates "determined" from "frozen"), so prefer it on
  - `lisp/maxterm.lisp` — FiFO→max-term bridge: `(marginals-maxterm ...)`, `--solver max-term`. NOT a Gibbs marginal — `logit P(a) = beta*(c_min(¬a) − c_min(a))` from 1+n MaxSAT solves (the unconstrained optimum supplies one polarity per atom), i.e. R&G's recognizer with the hypothesis replaced by an atom. Drops the degeneracy term, so it approximates what the WEIGHTS contribute and discards what the COUNTING contributes — on an unweighted theory it returns 0.5 for everything. Output is `(MAXTERM-MARGINAL ...)` deliberately, so `grep MARGINAL` cannot pick it up. Exact on backbone atoms (flagged `[proved]`). Exclusive groups are DETECTED from the theory (at-least-one clause + pairwise at-most-one), never declared in the query — the exact back ends need no declaration, so the query should not repeat what the theory says; `--verify-groups` proves them by SAT instead. At-most-one-but-not-exhaustive groups get a virtual "none" cell. Priors are post-hoc log-odds shifts needing NO re-solve, because a unit cost factors out of the minimisation — exact for the atom it is on, wrong for every other. Uses FiFO's `shift-and-scale-weights`/wcnf writer: raw real weights make a MaxSAT solver emit no objective at all. **Needs an EXACT MaxSAT solver** — default `bin/rc2-maxsat.py` (PySAT RC2, core-guided, prints `s OPTIMUM FOUND`), found beside the script rather than on PATH since FiFO ships it; `--maxsat-solver` selects another. The anytime solvers (tt-open-wbo-inc, nuwls-c) NEVER prove optimality, and since the estimator is a DIFFERENCE of two minima their upper bounds do not cancel; `mt--solve` returns `:unproved` for those and `marginals-maxterm` counts and warns. (Measured on pb1: 15 of 16 solves unproven with the anytime solver, though the values happened to be identical — and rc2 was 2.7x faster.) EvalMaxSAT works, but on macOS ONLY when built with Homebrew GCC — the Apple-clang build compiles cleanly and segfaults instantly, so install-solvers.sh passes a `g++-N` to its cmake (`/usr/bin/g++` is a clang shim). It exits 30 on success, which is fine since `solver-verdict` reads the `s` line.
  - `lisp/hypotheses.lisp` — posteriors over a set of competing hypothesis atoms: `(hypothesis-posterior scnf &key hypotheses evidence baseline counter priors ...)`, behind `marginals.sh --hypotheses`. Dispatches to all six back ends; see the `marginals.sh` entry above for the identity, the guards and the `Weights` trap.
  - `lisp/wmc.lisp` — FiFO→ADDMC bridge: `(wmc ...)` weighted model count and `(marginals-addmc ...)` marginals via the external ADDMC counter (emits MCC weighted CNF, shells out, parses the count)
  - `lisp/ddnnf.lisp` — FiFO's own pure-Lisp d-DNNF compiler + circuit evaluator (no external binary). `(ddnnf-compile ...)` trace-compiles the hard clauses (grown from maxent's DPLL: decisions→OR, disjoint components→AND, component cache→DAG; smooth-by-construction) into a circuit; `(ddnnf-query ...)`/`(ddnnf-marginals ...)` get Z and ALL marginals in two passes. Unit-literal evidence reuses the compiled circuit (compile-once/query-many); non-unit evidence recompiles from the stored clauses. `(ddnnf-save ...)`/`(ddnnf-load ...)` persist a circuit to a readable `.dnnf` file (`(ddnnf-marginals-sets ...)` queries many evidence sets against one compile). Node cap `*ddnnf-node-limit*`; FiFO-scale instances only — use ADDMC for large/high-treewidth ones. `(ddnnf-compile-d4 ...)` is an alternative producer: it shells out to the external **d4** (d4v2) compiler (`*d4*`, on PATH), parses + smooths its arc-format dump into the SAME struct, so all of query/evidence/persistence is reused (d4 compiles only the Boolean structure; weights stay on the FiFO side). `ddnnf-marginals` takes `:compiler :home|:d4`
  - `lisp/satplan.wff` — domain-independent SatPlan axioms (a runtime dependency)
  - `lisp/solvers.dat` — the SINGLE SOURCE OF TRUTH for which external solvers and marginal counters exist, their abbreviations and their kinds (a runtime dependency). Read by BOTH `bin/fifo-solvers.sh` and `lisp/FiFO.lisp` (into `*solver-table*`, `*solver-abbreviations*` and `counter-names`), so adding a solver means editing that file and NOTHING else — it replaced two hand-kept copies carrying a comment asking that they be kept in step, which is a request, not a mechanism. Whitespace-separated `type name kind flags abbrevs install`; `#` comments; `-` is empty. The `no-planner` flag carries the one context asymmetry: `marginals.sh --solver` offers six counters and `planner.sh --counter` five, since max-term needs a NAMED query while `--marginals` reports every atom. `FIFO_LISP` is AUTHORITATIVE when set — the table must come from the same directory as the FiFO.lisp being loaded and no fallback is tried, since resolving names from one table while the Lisp reads another is exactly the drift this removes.
- `bin/` — Shell scripts: `solve.sh` (satisfiability CLI: fixes plain CNF, default `kissat`) and `map.sh` (MAP inference CLI: fixes weighted CNF, default `tt-open-wbo-inc-Glucose4_1`, `--preprocessor maxpre`, and prints the TRUE cost = raw objective/scale + offset by pinning `scratch-file` so it can read the wcnf's comment lines — note that root must contain no `.`, since FiFO derives `.satout` from the FIRST dot in the path); both render the answer via `fifo-answer.sh` (`_fifo_print_answer`): the `.answer` file VERBATIM plus leading `;` comment lines, so `grep -v '^;'` is exactly the machine-readable form — needed because `solve` returns only the verdict symbol, so printing its return value alone DISCARDS `prove` answer-extraction bindings. EVERY place any script accepts a solver, counter or preprocessor name now goes through `fifo-solvers.sh` (`_fifo_require_solver` / `_fifo_require_counter` / `_fifo_require_preprocessor`), which resolves abbreviations, refuses an unknown name (naming `solvers.dat` and the line to add), refuses the wrong KIND, and checks the binary is installed — all from `lisp/solvers.dat`. Two carve-outs: a name containing `/` is an explicit path, checked for existence and classified by basename but needing no entry (marginals.sh's own default `bin/rc2-maxsat.py` is one); and a `bundled` solver is looked for beside the scripts rather than on PATH. The kind check prevents a SILENT failure: weights in a plain `.cnf` become `cw` comments a SAT solver ignores, yielding a non-optimal model. The EXISTENCE check prevents a duller one: `planner.sh` used to accept any string, so a typo surfaced inside `sb-ext:run-program` AFTER translation and instantiation, once per horizon — and `recognize.sh` forwarded it into 3n such runs; both now validate before anything is translated. `planner.sh`'s `--minslices` error path also used `${v,,}`, which is bash 4.0+ while its `#!/bin/bash` is 3.2 on macOS, so the error path itself errored. `planner.sh` (planner CLI), `learn.sh` (scnf weight-learning CLI), `learn-pddl.sh` (PDDL weight-learning CLI), `marginals.sh` (marginal inference on an scnf; `--solver maxent` enumeration (default), `--solver addmc`, `--solver ddnnf` (FiFO's own d-DNNF compiler), or `--solver d4` (compile the structure with the external d4 compiler, same circuit machinery); `--save-circuit`/`--circuit` persist & reuse a compiled circuit for ddnnf/d4; `--solver mc-sat` is the approximate MCMC back end — one WalkSAT-v58 `-mcsat` run gives all marginals, with `--samples`/`--burnin`/`--seed`/`--unitprop`/`--walk-prob`/`--temp`/`--samplesat-cutoff`/`--init-cutoff`/`--init-tries`/`--no-sat-seed`. `--hypotheses <atom>`/`--hypotheses-file` treat a set of atoms as COMPETING HYPOTHESES and report `(HYPOTHESIS ...)` rows (never `(MARGINAL ...)`) instead of per-atom marginals, with `--baseline best-rival|per-hypothesis` choosing WHICH PRIOR is in play: best-rival (the default, today's behaviour) is `P(h|T,O)` off one conditioned model, whose prior is IMPLICITLY `P(h|T)` — the theory's own mass on h, so whichever hypothesis has the most models wins regardless of the evidence; per-hypothesis divides that out and applies `--prior` instead, giving R&G's likelihood `P(O|T,h)`. For the EXACT counters per-hypothesis costs one extra run TOTAL, not one per hypothesis, via `P(O|T,h) = P(h|T,O)·P(O|T)/P(h|T)` where `P(O|T)` is constant in h and cancels on normalisation — so the posterior is `prior·P(h|T,O)/P(h|T)`, two runs and a division. That identity needs neither reification nor negation of O (so evidence may be any set of ground formulas) and works on `maxent`, which has no `:evidence` keyword, because conditioning is done by CONJOINING the evidence clauses into a combined scnf the way `plan--scnf-to-solve` does. max-term cannot use it — it drops degeneracy differently on each side — so it computes R&G's difference directly, 2n clamped `mt--solve` calls of `c_min(T∧O∧h)` vs `c_min(T∧¬O∧h)`; it is the ONLY case needing ¬O, built internally as `(not (and ...))` so several evidence forms are still fine. A hypothesis or evidence atom the theory does not contain is an ERROR: FiFO mints a fresh proposition for it, which occurs in no other clause, so it would constrain nothing and the answer would silently be the unconditioned one — note an scnf writes a 0-ary predicate as `P`, not `(P)`. The header says whether exclusivity is ENTAILED (via `mt--detect-groups`) or merely ASSUMED, since normalising over the set presumes it. Fixing the guard that refused `--evidence` for max-term exposed a live bug it had been masking: `Weights` is FiFO's global special and `(parse ...)` inside `wmc--evidence-clauses` resets it, so binding the scnf's weight forms to that name — as `maxterm.lisp` did — silently emptied them and max-term returned its unweighted answer, 0.5, for every atom; `wmc`/`ddnnf`/`mcsat` already used `weight-forms` for exactly this reason), `wmc.sh` (weighted model count / partition function via ADDMC), `recognize.sh` (Ramírez & Geffner plan recognition: the calibrated posterior `σ(β·(c(¬O)−c(O)))·prior` per hypothesis derived predicate hypI, normalized over the hypotheses; the tractable MaxSAT approximation to the intractable Z_G-normalized WMC posterior. It instantiates the problem ONCE at the horizon and clamps 2n solves on that single scnf via `marginals.sh --hypotheses --baseline per-hypothesis`, rather than calling `planner.sh` 2n times: clamping hypI in the DISJUNCTIVE theory selects the same models as rewriting the goal to Gi, since hypI implies the disjunction (`T∨ ∧ hypI ≡ Ti`), so it is the same computation — measured with byte-identical summary.tsv, and 4.1 s against 28.6 s on IntrusionDetectionCosts at horizon 6 (same exact solver on both sides). `(occur-in-order …)` reaches that single scnf through a SPLIT: its translation is `(and <monitor axioms> <assertion>)` (`occur-in-order-split`), the axioms are biconditional and so count-neutral — verified: adding them leaves all 21 Switch marginals unchanged — so `planner.sh --split-evidence` folds them into the theory and writes the one assertion literal to `<root>-assertion.txt`, RESOLVED (the source form says `numslices`, which is bound only in the instantiation env; an unresolved symbol would name an atom the theory lacks and so constrain nothing). Conditioning on that literal is the comply case, its negation the does-not-comply case, from one instantiation. `--maxsat-solver` picks the solver producing the COSTS, defaulting to the EXACT bin/rc2-maxsat.py and used by BOTH paths: R&G's score is a DIFFERENCE of two minima, so an anytime solver gives two upper bounds that do not cancel — the plan-runs path silently had this, since planner.sh's default weighted solver is anytime, which made repeated runs disagree AND was slower (120 s vs 28.6 s for identical work). `--counter` picks the back end (default max-term) and `--baseline` the prior; `--solver` still means the SAT solver used by the horizon search, which is the one part still costing n planner runs. HYPOTHESES come from PARSING the problem's `:goal` and taking its disjuncts, and the criterion is ARITY — a hypothesis is a NULLARY predicate, so `(hyp0)` qualifies and `(at p1 bos)` does not, which keeps an ordinary disjunctive planning goal from being read as a recognition instance; `hypI` is a convention, not a requirement, and `(preference ...)` forms in the goal are skipped rather than taken as disjuncts. It used to grep the raw problem TEXT for `(hyp[0-9]+)` and match `--priors` to the result BY LINE NUMBER, two fragilities that compounded: a `(hyp7)` in a COMMENT was picked up as a hypothesis, and because priors were positional that did not merely add a spurious row, it shifted every later weight onto the wrong hypothesis, silently. PRIORS are now given BY NAME — `--prior hyp0=9`, repeatable, or `--priors FILE` of `hyp = w` lines — as RELATIVE weights renormalised (2 and 1 mean 2/3 and 1/3), unnamed hypotheses keeping weight 1, an unknown name an ERROR listing the real ones, and the old bare-number file REFUSED with the new spelling shown. `--priors-from-preferences` is the third source: it reads `(preference <name> (hypI) w)` from the goal as `pi ∝ exp(w)` — a PDDL preference weight is a VIOLATION penalty, so escaping it is worth odds exp(w) and no preference means w=0, hence pi ∝ 1 — and it STRIPS those preferences before instantiation, so the weight is the prior and is not ALSO charged as a cost. Stripping is what makes it exact: a weight left in the theory cancels between c(G,O) and c(G,¬O) only if the hypotheses are mutually exclusive, and IntrusionDetection's are not (delete-free domain), so the optimiser can satisfy a different set of OTHER hypotheses on the two sides and leave a second-order residual. Refused under `best-rival` (where the weight is not cancelled at all) and alongside `--prior`/`--priors`. One conversion is load-bearing at the boundary: recognize.sh's priors are RELATIVE WEIGHTS but `marginals.sh --prior` takes a PROBABILITY, and max-term turns a prior into a per-atom LOG-ODDS SHIFT — so forwarding the default weight 1 as if it were a probability asks for logit(1) = infinity and pinned every max-term marginal at 1.0, making best-rival report a flat prior as its posterior. They are normalised before forwarding, and NOTHING is forwarded when the user gave no prior, since a uniform shift does not cancel in log-odds space — 'uniform' and 'absent' are different requests there. The regression test for it requires the best-rival posterior to VARY: summing to 1 passes vacuously on a flat 0.1 across ten hypotheses, which is exactly what the broken version returned. `--method plan-runs` keeps the old 2n-planner-run implementation as the oracle the fast path is tested against; it always computes R&G's difference, so `--counter`/`--baseline` are REFUSED with it rather than silently ignored. P=0.0000` instead of erroring; and `rc2-maxsat.py` passing validation without python-sat, since a path is only checked for executability — every solve then fails and every cost is NA. `--maxgoals N` (N<=3, REQUIRES `--preferences`, default = the package count = no constraint) caps how many deliveries may hold, encoded as one `(not (and ...))` per (N+1)-subset of the goal atoms — which is why N is capped, since the count grows as packages^(N+1); `--goals-per-package N M` (also REQUIRES `--preferences`) gives each package N alternative destinations rather than one — only one can ever hold, since a package is at one place, so they are genuine alternatives sharing the L..H weight spread — with M (0 or 1) the minimum number of HARD goals per package: M=1 emits one disjunction PER PACKAGE (every package must arrive somewhere it wants) in place of the single global one, which any of them implies. `--seed` fixes the draws; without it the clock seeds and the value is still RECORDED, and every generated file opens with the full settings block (defaults included, style-relevant only) that regenerates it byte for byte — `--maxgoals` excepted, recorded only when GIVEN, since its unset value is "no cap", which has no command-line spelling: writing the old default (the package count) back out produced a block that could not replay, being both >3 and paired with `--preferences none`. They live under `SatPlan/` rather than `bin/`+`lisp/` because they are domain-specific, not part of the installable library. `SatPlan/evgen.sh` + `evgen.lisp` are the companion EVIDENCE generator for plan recognition (domain-independent, but shelved beside ppgen): given a problem and the `.answer` planner.sh wrote for it, `--slices "1-3,5"` emits the fluents and actions true at those slices as FiFO forms for `planner.sh --evidence-file`, with `--observe "fly,in"` restricting to named fluents/actions and `--negative-evidence 1` also recording what is FALSE. It emits FiFO forms, not PDDL modal ones, because only these can pin a FLUENT to a slice — the modal `at` takes an ACTION and `hold-during` takes a range. `--recognition 1` makes the file usable by `recognize.sh --evidence-kind fifo`: it writes ONE `(and ...)` form instead of a literal per line, which is the whole requirement, since recognize.sh builds the does-not-comply case by wrapping the file's contents in `(not ...)` and `(not A B)` is not a formula (recognize.sh now REFUSES a multi-form file rather than emit that, and names `--recognition 1` in the message — the guard covers the PDDL path too, where the same shape was a SILENT bug: `(not A B)` is read as `(not A)`, so a second observation vanished from the not-comply case while the comply case still used it, leaving the two costs incomparable; measured, `(not A)` and `(not A B)` are both UNSAT where `(not (A B))` costs 14). It also refuses `--negative-evidence 1`, which would collapse the posterior to 0/1. Prefer `--observe` over ACTION names: an action at slice s means slice s at any horizon, but a fluent at the FINAL slice means "at the end" only at the horizon it came from, and recognize.sh picks one horizon for all hypotheses — which it also raises to the largest slice the evidence names, since slice-pinned evidence is unsatisfiable below that and every posterior would be 0. evgen cannot leak a hypothesis: `hypI` are DERIVED predicates and evgen emits from the `fluents` domain, which derived predicates are kept out of. `--export-dataset <dir>` writes the instance in the RAMIREZ & GEFFNER DATASET FORMAT instead — `domain.pddl` (hypothesis rules stripped), `template.pddl` (goal = the `<HYPOTHESIS>` placeholder), `hyps.dat`, `obs.dat`, `real_hyp.dat`, README — for tool chains that do not read FiFO. It is the exact INVERSE of `SatPlan/Examples/Plan_Recognition/make-recognition-instance.lisp`, so the round trip closes and is tested (export → re-import → solve under the exported obs.dat, observations embedding at increasing slices); the exported `hyps.dat` also reproduces the PUBLISHED `IntrusionDetection/hyps.dat` hypothesis for hypothesis. Needs a recognition instance — a goal that is `(or (hyp0) ... (hypN))` of nullary derived predicates, which supplies hyps.dat's ORDER while the domain's `(:derived (hypI) ...)` rules supply its content; anything else is refused. `real_hyp.dat` is READ from the answer's `(HOLDS (hypI) numslices)`, not guessed. Costs are KEPT (an added cost is indistinguishable from an original one, and `add-cost-to-action` skips an action that already has one, so the round trip does not double them). Two limits, repeated in the exported README: obs.dat holds ACTIONS only (a fluent in `--observe` errors, `--negative-evidence 1` is refused), and it is a linear sequence while FiFO slices are PARALLEL, so same-slice actions come out consecutive in an arbitrary order. `--export-constraints <dir>` is the OTHER export, making the opposite trade: it writes the problem with the observations in a `(:constraints ...)` section at their EXACT slices — `(hold-during t t <fluent>)`, standard PDDL 3.0, and `(occur-sometime t t <action>)`, which is NOT (every standard con-GD operand is a STATE formula, so the standard cannot say an action occurred; occur-sometime is FiFO's own). A file containing action observations therefore OPENS WITH A COMMENT naming that requirement, so a recipient learns it from the file rather than a parse error; a fluents-only export omits the note and is plain PDDL 3.0. It writes domain.pddl (unchanged but for `:constraints` in `:requirements`), problem.pddl and a README; needs NO recognition instance, unlike --export-dataset; and keeps fluent observations, which obs.dat cannot represent. `--negative-evidence 1` refused — `(hold-during t t (not f))` would do a negative fluent but nothing says an action did NOT occur. `--export-ordering-constraints <dir>` is the third: ONE `(occur-in-order M N a1 ... ak)` carrying the observations' order and the span they fell in, without pinning any to a slice. Its caveat comment is UNCONDITIONAL — unlike hold-during there is no standard fallback at all. Two observations in the SAME slice are REFUSED, naming the slice: occur-in-order needs strictly increasing slices while FiFO's are PARALLEL, so writing them as a sequence would claim they happened at different slices and the export could come back UNSAT. `--nonstrict-ordering 1` emits `occur-in-nonstrict-order` instead and ACCEPTS the tie, which is the usual answer on a parallel domain. Note `--observe` filters by predicate NAME, so it cannot separate two groundings of the same action — the message says so, and points at `--slices`, `--export-constraints` and `--nonstrict-ordering 1`. Choose between them by what the recipient runs: --export-dataset is order-only and universally readable, --export-constraints keeps the times but needs a planner extended for occur-sometime. Since FiFO reads this dialect the export is verified by SOLVING it — the exported problem must hit the source plan's cost, and moving one constraint to another slice must break it. Everything emitted is validated against the problem's real ground universe, re-derived by parsing the wff with `*satplan-numslices*` bound to the solution's horizon and reading `FLUENTS`/`ACTIONS` out of FiFO's global `Bind` (NOT from the `.map` beside the solution, which `cleanupfifo.sh` deletes). That validation now doubles up with `plan--resolve-evidence` (see `lisp/planner.lisp` above, which closed the same hole on the planner side); evgen's is the earlier line, failing at generation time against the SOLUTION's horizon rather than the planner's working one. An out-of-range slice, an unmatched `--observe` name, a non-SAT solution file and an empty selection are each an error. Note fluents run slices 1..N but actions only 1..N-1, so `--slices N` yields fluents only; and `--observe` restricts NEGATIVES too, which it must — one slice of unrestricted negative evidence on a toy 3-package problem is 341 literals (45 fluents + 296 actions), and negative evidence asserts COMPLETE observability, which collapses a recognition posterior rather than sharpening it

## Key APIs (in lisp/FiFO.lisp)

- `(parse schemas &key static-list)` — Parse FiFO forms to ground clauses (all post-first args are keyword args; `:observation-list` is a deprecated synonym)
- `(instantiate "file.wff")` — File-based: wff -> scnf
- `(propositionalize "file.scnf")` — File-based: scnf -> DIMACS cnf + map
- `(satisfy "file.cnf")` — Run SAT solver (default: kissat)
- `(interpret "file.satout")` — Map SAT output back to symbolic literals
- `(solve "file.wff")` — End-to-end: wff -> solution

## Running

Requires SBCL with Quicklisp. The SAT solver defaults to `kissat` (configurable via `sat-solver` variable).

The weighted-model-counting bridge (`lisp/wmc.lisp`, `bin/wmc.sh`, `marginals.sh --solver addmc`) shells out to a separate **ADDMC** executable — a macOS fork at `github.com/HenryKautz/ADDMC` (built locally at `../ADDMC/addmc`). It is found on `PATH` as `addmc` (the `*addmc*` lisp variable names it — no env var, no `--*-bin` flag: use a different build by putting it earlier on `PATH`). ADDMC is optional — only the WMC features need it.

`marginals.sh --solver mc-sat` (and `marginals-mcsat` in `lisp/mcsat.lisp`) shells out to **WalkSAT version 58 or later** — `gitlab.com/HenryKautz/Walksat`, the `Walksat_v58_MC-SAT` directory, built locally at `../Walksat/Walksat_v58_MC-SAT/walksat`. Found on `PATH` as `walksat` (the `*walksat*` lisp variable). Optional — only `--solver mc-sat` needs it. A pre-v58 walksat has no `-mcsat`, so both the shell script and the test suite probe `-help` for `-mcsat` and refuse/skip rather than silently running the wrong thing.

Similarly, `marginals.sh --solver d4` (and `ddnnf-compile-d4` in `lisp/ddnnf.lisp`) shells out to the **d4** (d4v2) d-DNNF compiler — a macOS fork at `github.com/HenryKautz/d4v2`, whose `demo/compiler` is built locally at `../d4v2/demo/compiler/build/compiler`. Found on `PATH` as `d4` — d4v2 builds it as `demo/compiler/build/compiler` and `install-solvers.sh` installs it under the short name (the `*d4*` lisp variable). Optional — only `--solver d4` needs it. d4 compiles only the Boolean structure; FiFO smooths the dump and applies weights at the leaves, reusing all the ddnnf circuit machinery.

**Important:** SBCL on this system requires `--eval` (long form); `-e` is not recognized and silently drops all eval forms.

## Testing

All test files and scripts live under `tests/`. Two test runners (must be run from inside `tests/`):

```sh
cd tests
bash run-test-instantiate.sh <testname>   # e.g. bash run-test-instantiate.sh test_all_exists
bash run-test-solve.sh <testname>         # e.g. bash run-test-solve.sh test_simple_deduction
```

`run-test-instantiate.sh` runs `instantiate` on `tests_instantiate/<testname>.wff`, writes `tests_instantiate/<testname>.scnf`, and cats the output.

`run-test-solve.sh` runs `solve` on `tests_solve/<testname>.wff`, writes `tests_solve/<testname>.answer`, and cats the output.

`tests/run-test-pddl.sh` (runnable from anywhere) is the PDDL-translator regression suite: for every example problem with a checked-in translation under `SatPlan/Examples/` (LogisticsCosts pb1–pb7, TruckLog, Switch, LogisticsPrefs, Plan_Recognition), it runs `pddl2fifo` on a temp copy and diffs the wff byte-for-byte against the checked-in one (the `(include ...)` satplan path is normalized). Update the checked-in wffs whenever emitter output legitimately changes. It also carries one behavioral case for that include path: `planner.sh --stop-after scnf` on a problem reached through a SYMLINKED directory. `planner.sh` computes the path with `File::Spec->abs2rel`, which is purely lexical, while FiFO resolves the include against the wff's TRUENAME — so both sides must be `pwd -P` first or the relative path comes out short by however many components the link crossed, and satplan.wff is looked for in a directory that does not exist. On macOS that was every problem under `/tmp` (really `/private/tmp`); the other suites never caught it because they all `pwd -P` their own temp dir.

`tests/run-test-evidence.sh` (runnable from anywhere) is the `--pddl-evidence` regression suite, chiefly for `occur-in-order`: behavioral checks (plan embeds the observed sequence at strictly increasing slices; bad evidence raises its contextual error), not gold diffs — evidence clauses can contain session-varying gensyms.

`tests/run-test-mcsat.sh` (runnable from anywhere) is the MC-SAT back-end suite: behavioral, not gold diffs (the output is a Monte-Carlo estimate). Each case fixes `--seed` and asserts the sampled marginals match the exact `maxent` ones to a tolerance — mixed-sign costs, the closed-form `sigmoid(-c)` on a free atom, uniform sampling of pure hard clauses, the header `scale:`, reified formula weights under `--weighted-only`, `--evidence` vs. the same clause asserted, `--unitprop` invariance, seed reproducibility, the ESS diagnostic, UNSAT hard clauses, CDCL seeding on and off, the mixing diagnostic, that a genuinely determined theory is NOT called frozen, and the wrong-version guard. **Skips cleanly (exit 0)** when no WalkSAT v58 binary is found, like the other optional-dependency back ends.

`tests/run-test-ppgen.sh` (runnable from anywhere) is the `ppgen.sh` suite: structural checks against `SatPlan/ppgen-specs.txt` rather than gold diffs, since the output is random — one airport per clique, roads joining every pair within a clique and none between, grid roads only between adjacent cells, airports at the provably maximal minimum separation (checked by brute force), even spread of packages/trucks/airplanes, complete two-way routes, no package already at its goal, cost defaults and overrides, the preference mode (disjunctive goal, equally-spaced weights, random assignment order), `--maxgoals` (the exact (N+1)-subset encoding, a vacuous cap emitting nothing, and the cap holding in a solved plan), `--goals-per-package` (N distinct destinations per package, none at its start, indexed preference names, the weight spread still exact over all packages×N goals, M=0's single global disjunction vs. M=1's per-package ones, and M=1 honored in a solved plan), the recorded settings block, an unseeded run whose recorded seed reproduces the file exactly, the whole settings block replaying byte for byte, `--output`, eighteen error paths, and a solvability check per style (which skips without a MaxSAT solver).

`tests/run-test-action-costs.sh` (runnable from anywhere) is the problem-file action-cost suite: behavioral, not gold diffs — a 0-ary function's value reaches the schema, the same domain gives different costs under two problems, a parameterized function produces per-grounding `(cost ...)` facts and leaves the schema costless, literal costs still work, the costs drive the optimum end to end (the cheap detour beats the direct move), and each of the six error paths fires (missing value, undeclared function, arity mismatch, non-zero `total-cost`, an unvalued grounding, an action writing a cost function). The end-to-end case skips cleanly when no MaxSAT solver is present.

`tests/run-test-cleanup.sh` (runnable from anywhere) is the `cleanupfifo.sh` suite: it deletes files, so what it mostly tests is what must NOT be deleted, and every destructive case runs against a throwaway git repository built in a temp dir — never the real checkout. Covers the sweep, the git-tracked guard, `tests/` being untouched tracked or not, the refusal of an explicit `tests/` target, `--dry-run`, a plain directory outside any repository, `-r`, an installed copy with and without `FIFO_LISP`, and a run under `/bin/bash` (3.2 on macOS, which is what the shebang actually gets — `bash` on PATH is 5.x). It also covers `make-scratch-file-root`: four concurrent SBCLs must produce four DISTINCT roots. They used to produce one — SBCL starts every process with an identical `*random-state*`, so `(random n)` returned the same suffix every run and `get-universal-time` is only second-granular, meaning concurrent runs in one directory silently read and deleted each other's `.cnf`/`.satout`. The root now carries the pid, and the random half draws from a clock-seeded `*scratch-random-state*`.

`tests/run-test-evgen.sh` (runnable from anywhere) is the `evgen.sh` suite: behavioral, against a ppgen fixture solved by planner.sh — the emitted positives are EXACTLY the solution's true literals at the requested slices, `--observe` restricts (including the spec's mixed fluent+action `"fly,in"` case), positives and negatives partition the restricted universe with no atom in both polarities, the settings header replays byte for byte (in both modes), the defaults for `--solution`/`--domain` resolve, `--recognition 1` emits exactly ONE form carrying the same literals as the default mode, and the recognize.sh guards fire (a multi-form file refused with the fix named, a single-form one accepted, the horizon raised to the largest slice observed, a bad `--evidence-kind` refused). `--export-dataset` is covered by a full round trip against a REAL benchmark: export from IntrusionDetectionCosts, check `hyps.dat` against the published `IntrusionDetection/hyps.dat`, re-import through make-recognition-instance.lisp, and solve the result under its own obs.dat. NOTE the fixture solves a SINGLE hypothesis, not the disjunctive problem — the latter's cheapest plan is hyp0, 20 actions needing a 21-slice horizon to re-check — while the EXPORT still runs against the disjunctive problem, which is what carries the hypothesis set. NOTE the fixture discipline: planner.sh REWRITES `<problem>.answer` on every run and the binding cases run it WITH evidence, so the suite snapshots the pristine answer and generates from that — without it a later case silently observes an earlier case's conditioned plan, which is exactly how the recognition cases first failed. Two cases carry the weight: conditioning on the true observations reproduces the plan's cost while shifting ONE observed action to another slice costs more (proving the evidence actually binds rather than being silently vacuous), and the last slice must carry no actions under `--negative-evidence` — the positives-only version of that check passes VACUOUSLY, since nothing is true at slice N anyway, so an emitter that dropped the actslices bound looked identical until the negative case was added. Skips cleanly (exit 0) with no MaxSAT solver, since the fixture must be solved first.

`tests/run-test-hypotheses.sh` (runnable from anywhere) is the `marginals.sh --hypotheses` / `--baseline` suite: behavioural, against a fixture counted BY HAND, where h1 has four times the models of h2 but the evidence supports the two equally — so best-rival gives 4/5 vs 1/5 and per-hypothesis gives 1/2 vs 1/2, which is the whole point of the option in one number. Mutation-checked: dropping the division reddens 6 cases, dropping the stray-evidence guard 1, and reverting `maxterm.lisp` to HEAD reproduces the 0.5 bug. maxent/ddnnf need no binary; addmc/d4/max-term skip cleanly.

`tests/run-test-recognize.sh` (runnable from anywhere) is the merged-fast-path suite. The load-bearing case checks `--method fast` against `--method plan-runs` — an INDEPENDENT oracle, not numbers recorded in the test — so it really tests `T∨ ∧ hypI ≡ Ti` rather than the arithmetic. It also tests count-neutrality of the monitor axioms DIRECTLY (everything else rests on it), that the assertion literal is resolved rather than carrying `NUMSLICES`, that the negated form flips only the assertion, that c(O)/c(¬O) survive into summary.tsv, the flags, and slice-pinned FiFO evidence through the same path. Skips cleanly without a MaxSAT solver. Also every finding from that review: --help documenting the new flags (the first version of that check ended in `|| true`, so it asserted nothing), --counter/--baseline refused under plan-runs, --priors actually REACHING marginals.sh, a stale scnf not passing for a fresh run, and the script running under /bin/bash 3.2. For hypothesis discovery and priors: a `(hypN)` in a COMMENT is not a hypothesis (the case the old grep failed), the same weights in a different ORDER give an identical summary (the whole point of naming them), a non-nullary disjunct and an unknown prior name are refused, and the old positional file is refused with the new spelling. `--priors-from-preferences` is pinned EXACTLY — `(preference h0 (hyp0) ln 2)` must give the same posteriors as `--prior hyp0=2` with no preference, which fixes pi ∝ exp(w) rather than any nearby formula — and its costs must match the preference-free problem, which is what proves the strip.

### Known issues

- Nested `exists` with `(option compact-encoding 0)` causes exponential clause blowup (cross-product expansion). Keep domains small (≤3 values) or omit the option to use Tseitin encoding.
- `test_nested_exists_nocompact.wff` uses 3 boys / 2 girls to stay tractable with compact-encoding disabled.
- `test_nested_exists_compact.wff` uses full 4-boy / 4-girl domains with compact-encoding enabled.
